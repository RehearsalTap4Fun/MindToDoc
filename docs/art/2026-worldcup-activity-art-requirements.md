# 2026世界杯主题活动美术需求

**整理日期**：2026-06-02
**来源文档**：`output/2026世界杯主题活动-开发文档.md`
**适用范围**：移动端 iOS / Android，竖屏单手操作，主游戏内限时活动。

## 1. 美术目标

本活动需要在世界杯期间快速建立“足球主题 + 球星生涯 + 轻操作小游戏”的识别度。美术应服务三个目标：

- **主题辨识**：第一屏能明确感知世界杯/足球/俱乐部赛事氛围。
- **操作清晰**：切片玩法中的球、球员、门将、轨迹、落点和道具状态必须清楚，不能被装饰干扰。
- **活动商业化**：BP、礼包、兑换商店、排名奖励需要有足够吸引力，但整体仍保持活动页签的高可读性。

建议风格为“明亮竞技体育 + 活动庆典包装”，避免过暗、过写实或过复杂的球场画面影响移动端操作判断。

- 三级视觉：金币、门票、竞猜币、局内道具、局外道具、外观券。

### 3.5 切片球员模型与动作

切片玩法的核心可先采用“轻量 3D 模型 + 少量关键动作 + UI 轨迹辅助”的方案，不追求完整足球比赛模拟。动作以服务切片结果表达为主，优先保证读秒、出脚、扑救、成功/失败反馈清楚。

#### 3.5.1 模型需求

| 模型 | 数量 | 用途 | 优先级 | 备注 |
|------|------|------|--------|------|
| 主角球员模型 | 4 | 创角展示、控球球员、签约亮相、庆祝 | P0 | 与 4 个角色外观一致，可共用骨骼 |
| 通用队友球员模型 | 1-2 | 助攻、接应、跑位、禁区站位 | P0 | 可通过球衣颜色/号码区分 |
| 通用对手球员模型 | 1-2 | 防守、出球、界外球干扰 | P0 | 可与队友共骨骼换材质 |
| 门将模型 | 1 | 任意球、点球、守门切片 | P0 | 需要明显区别普通球员 |
| 人墙球员模型 | 1 | 任意球墙体站位 | P1 | 可复用通用对手模型，固定站姿 |
| 系统补位球员模型 | 1 | 淘汰赛补位、回放展示 | P2 | 可复用通用队友模型 |

模型制作建议：

- 所有球员优先共用同一套人形骨骼，减少动作制作和运行时成本。
- 主角 4 个外观只影响视觉，不绑定数值差异。
- 队友/对手优先通过球衣主色、号码、队徽贴图区分。
- 移动端竖屏中角色多为中远景，面部细节可简化，动作轮廓必须清楚。
- 模型需要支持左右镜像或朝向旋转，避免为左右脚/左右扑救重复制作大量资源。

#### 3.5.6 技术交付要求

- 模型需提供统一缩放标准和脚底原点，便于关卡切片按配置摆放。
- 动作需提供可循环标记，例如待机、短跑。
- 射门、传球、扑救动作需要标记关键帧事件点，用于同步足球发射、碰撞、扑救结果和镜头反馈。
- 回溯会重置球员和足球位置，模型状态需要能快速回到切片初始 pose。
- 切片配置已拆为 `slice_type_def / slice_preset / slice_instance` 三层；美术摆位预览应优先按 `slice_preset` 制作可复用画面，`slice_instance` 只做局部覆盖。
- 若引擎支持状态机，建议动作按 `idle / run / control / kick / pass / save / celebrate / fail` 分组。
- 若 3D 成本过高，MVP 可用 2D token + 少量序列帧替代，但接口命名仍按模型/动作需求预留。

## 4. P0 首批交付建议

为支持玩法和主流程开发，首批建议只做能覆盖核心链路的资产：

1. 4 个角色立绘/头像。
2. 国籍图标与基础球队徽章模板。
3. 主角、队友、对手、门将基础模型或 2D token。
4. 待机、短跑、控球、射门、传球、门将左右扑、庆祝、失败动作。
5. 竖屏球场背景、球门、足球。
6. 轨迹辅助线、落点、可操作夹角、反应时间条。
7. 哨子、回溯、瞄准 3 个局内道具图标。
8. 金币、门票、竞猜币、训练星 4 个资源/奖励图标。
9. 创角、切片操作、关卡结算、养成、训练关卡、积分赛 6 个核心页面 UI 皮肤。
10. 进球成功、失败、回溯重置、训练星获得 4 类基础反馈动效。

- 国籍/地区最终列表。
- 球队数量、球队星级上限、是否使用真实国家/俱乐部影射。
- 4 个角色的性别、年龄、体型、球衣风格和角色定位。
- 球衣是否需要可换肤，外观奖励是否落在球衣、鞋、发型、头像框或庆祝动作上。
- 切片玩法最终采用 3D 模型、2D token、序列帧，还是混合方案。
- 主角、队友、对手、门将是否共用骨骼与动作。
- 是否需要区分左右脚射门、不同射门力度和不同扑救高度。
- 训练关卡是否需要独立主题包装，还是复用积分赛/切片操作包装。
- 局外道具具体类型和数量。
- BP、排名、淘汰赛奖励的稀有度分级。
- 礼包和商店商品是否需要独立大图，还是只用图标。
- 是否需要适配多语言导致 UI 文本区域扩展。
- 是否存在 FIFA/世界杯官方授权限制，若无授权需避免直接使用真实标识、真实球队队徽和官方赛事 Logo。

## 8. 交付格式建议

### 8.1 图片资产

- UI 图标：PNG/WebP，透明背景，提供 1x/2x/3x 或按项目规范切图。
- 角色立绘：透明背景 PNG/WebP，需提供全身/半身/头像裁切。
- 球场背景：竖屏安全区版本，需标注 HUD、操作区、底部栏遮挡范围。
- 队徽/国籍图标：建议使用可缩放源文件，导出游戏所需尺寸。
- 3D 模型：建议 FBX/GLB，统一骨骼、统一比例、脚底原点，贴图尺寸按移动端预算确认。

### 8.2 动效资产

- UI 动效：优先 Lottie / 序列帧，按引擎支持确认。
- 比赛反馈：可先用轻量粒子、文字动效和镜头缩放实现。
- 开场视频：如制作成本高，MVP 可先交静态背景 + UI 过场。
- 球员动作：建议 FBX 动作片段或引擎可直接导入的动画 Clip；循环动作需标注 loop，出脚/扑救动作需标注事件帧。
