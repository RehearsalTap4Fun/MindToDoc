# K1新服大地图重构功能策划案 · 配置表结构（数值策划填表）

> **定位**：本文只描述数值、地图、活动策划在 Excel 中需要维护的配置结构，不包含存档、协议及运行时状态。
> **规则依据**：主策划案 [K1新服大地图重构功能策划案.md](K1新服大地图重构功能策划案.md)。
> **现状依据**：K1 客户端、服务端与配置仓库当前正式表及读取关系。
> **列级 SSOT**：现有字段以正式 Excel/XML 为准；“建议新增字段”须在正式 XML 建表或扩字段后成为最终表头。

# 配置改造总览

本功能不新建一张承载全部内容的大地图总表。配置按“场景与寻路、区域与刷新、战略格子与建筑、迷雾与邻接关系”分层维护，优先复用现有正式表，仅新增现有结构无法表达的堡垒四邻关系与服务器共享迷雾层级。

## 读取端标记

| 标记 | 含义 |
|------|------|
| `c` | 客户端读取，用于地图显示、交互和预览 |
| `s` | 服务端读取，用于地图生成、刷新、资格与战斗判定 |
| `cs` | 客户端和服务端均读取 |
| 工具产出 | 由地图工具生成，不由数值策划逐行填写 |

## 主要依赖关系

```text
SceneType
  -> MapTypeCfg
      -> NavMeshId -> NavMeshCfg / TileMeshCfg / GlobalObstaclesCfg
      -> NpcRefreshId -> D2NpcZoneCfg -> D2NpcBandCfg

UnionWarAreaCfg
  -> BuildingID -> UnionWarBuildingCfg（系统堡垒）
  -> ZoneID -> D2NpcZoneCfg.ID -> FogLayerCfg.ZoneIDs
  -> FortressAdjacencyCfg.AreaID / AdjacentAreaID

MapSizeCfg.RandomUnit
  -> RandomMapUnitCfg
      -> Type=1 -> UnionWarBuildingCfg（龙巢）+ AdjacentAreaIDs
      -> Type=2 -> UnionWarBuildingCfg（圣坛）+ HostAreaID
      -> Type=3 -> KingWarBuildingCfg（王座）+ HostAreaID
```

`MapSizeCfg` 只维护服务器尺寸方案和地图对象范围参数。服务端地图的实际宽高、可行走区域和阻挡以 `NavMeshCfg / TileMeshCfg / GlobalObstaclesCfg` 为准。

# 场景、尺寸与地图工具产物

## `MapTypeCfg`

来源：`MapType.xlsx`。

| 字段 | 类型 | 状态 | 读取端 | 说明 | 填表要点 |
|------|------|------|--------|------|----------|
| `Id` | int | 现有 | `s` | 场景类型 ID | 为新服普通大地图分配独立 SceneType，不复用 KVK SceneType |
| `NavMeshId` | int | 现有 | `s` | 寻路与地图骨架配置 ID | 必须能同时找到同 ID 的 NavMesh、TileMesh、GlobalObstacles 数据 |
| `NpcRefreshId` | int | 现有 | `s` | NPC 区域与刷新模板 ID | 对应 `D2NpcZoneCfg.MapId`，与旧服和 KVK 数据隔离 |

新服普通大地图逻辑上仍属于原服，不能因为复用 KVK 地图资产而直接使用 KVK 的场景类型和活动配置。

## `MapSizeCfg`

来源：`MapSize.xlsx`。

| 字段 | 类型 | 状态 | 读取端 | 说明 | 填表要点 |
|------|------|------|--------|------|----------|
| `CfgID` | int | 现有 | `cs` | 服务器尺寸方案 ID | 按现有服务器选型机制配置 |
| `SizeType` | int/enum | 现有 | `cs` | 地图尺寸档位 | 复用项目既有尺寸档位，不用该字段替代 NavMesh 宽高 |
| `FortSize` | int | 现有 | `cs` | 联盟要塞相关范围 | 新服关闭自建入口后仍需确认是否被通用逻辑读取 |
| `FlagSize` | int | 现有 | `cs` | 联盟旗帜相关范围 | 新服模板不投放旗帜，但保留安全值 |
| `DragonNestSize` | int | 现有 | `cs` | 龙巢范围 | 与新地图龙巢点位碰撞校验一致 |
| `ThroneSize` | int | 现有 | `cs` | 王座范围 | 与中心王座区一致 |
| `RandomUnit` | int | 现有 | `cs` | 随机地图单位数据集 ID | 指向新服专用 `RandomMapUnitCfg_<ID>`，不得复用旧服/KVK 点位数据集 |
| `CenterSize` | int | 现有 | `cs` | 中心区/黑土地范围 | 与中心圈地图资产一致 |

## `RandomMapUnitCfg`

来源：`RandomMapUnit/RandomMapUnit_*.xlsx`。服务端根据 `MapSizeCfg.RandomUnit` 动态加载对应数据集；现有类型为龙巢、圣坛和王座，点位初始化逻辑应继续复用。

### 现有字段

| 字段 | 类型 | 状态 | 读取端 | 说明 | 填表要点 |
|------|------|------|--------|------|----------|
| `ID` | int | 现有 | `cs` | 点位记录 ID | 数据集内唯一，服务端对象会保留该配置 ID |
| `Type` | enum/int | 现有 | `cs` | 随机地图单位类型 | 现有口径：1 龙巢、2 圣坛、3 王座 |
| `BuildingID` | int | 现有 | `cs` | 建筑配置 ID | 龙巢/圣坛关联 `UnionWarBuildingCfg.Id`；王座关联 `KingWarBuildingCfg.Id` |
| `PositionTuple` | position | 现有 | `cs` | 地图坐标 | 与地图工具、格子和建筑坐标系一致 |

### 建议新增字段

| 字段 | 类型 | 读取端 | 说明 | 填表要点 |
|------|------|--------|------|----------|
| `ZoneID` | int | `cs` | 点位所属地图区域 | 关联 `D2NpcZoneCfg.ID`，用于迷雾层级和区域校验 |
| `HostAreaID` | int | `cs` | 点位所在堡垒格子 | 圣坛和王座填写；龙巢位于格子交叉点时填 0 |
| `AdjacentAreaIDs` | int[] | `cs` | 为点位提供攻击资格的堡垒格子 | 龙巢填写 1 至 4 个；圣坛/王座按规则为空 |
| `DisplayPriority` | int | `c` | 地图展示优先级 | 只参与客户端图标排序 |

新服地图必须创建独立 RandomMapUnit 数据集，不能覆盖现有 `RandomMapUnit_1001` 等旧数据。`HostAreaID` 与 `AdjacentAreaIDs` 只描述静态点位关系，不保存运行时占领资格或归属。

## 地图工具产物

地图工具负责输出 `NavMeshCfg`、`TileMeshCfg` 和 `GlobalObstaclesCfg`。本文不为工具产物虚构 Excel 表头，但交付时必须同时提供以下结果：

- 新服地图实际宽高与 7200×7200 设计尺寸一致。
- 可行走区、出生区、中心王座区、边界不可用区和建筑阻挡一致。
- `MapTypeCfg.NavMeshId` 能加载同一套 NavMesh、TileMesh 和 GlobalObstacles。
- 地图工具坐标系与 `D2NpcZoneCfg`、`UnionWarAreaCfg`、`KingWarBuildingCfg` 使用同一原点、轴向和单位。

# 区域、出生与刷新

## `D2NpcZoneCfg`

来源：`D2NpcZone.xlsx`。新地图通过新增区域记录落地，不新增独立 `MapRegion` 或 `SpawnRegion` 表。

| 字段 | 类型 | 状态 | 读取端 | 说明 | 填表要点 |
|------|------|------|--------|------|----------|
| `ID` | int | 现有 | `s` | 区域记录 ID | 全表唯一，供格子与迷雾表引用 |
| `MapId` | int | 现有 | `s` | 区域所属刷新模板 | 必须等于新服 `MapTypeCfg.NpcRefreshId` |
| `ZoneId` | int | 现有 | `s` | 地图内区域编号 | 四个出生区、中间圈、中心圈和王座区分别编号 |
| `RectangleZone` | rect/list | 现有 | `s` | 区域矩形范围 | 多块区域按现有格式拆分或组合 |
| `AvailableSpace` | int/area | 现有 | `s` | 区域可用空间 | 用于出生容量和刷新空间判断 |
| `BandID` | int[] | 现有 | `s` | 区域刷新带 | 关联 `D2NpcBandCfg` |
| `RefreshOrder*` | int/list | 现有 | `s` | 各版本刷新顺序 | 按现有正式列维护，不新增同义字段 |
| `Level` | int | 现有 | `s` | 区域等级/圈层强度 | 出生区、中间圈、中心圈按主案梯度配置 |
| `ActivityInvasion` | bool/int | 现有 | `s` | 是否允许活动入侵 | 按新服活动投放需求配置 |
| `PlayerCityZone` | bool/int | 现有 | `s` | 是否为玩家出生城区域 | 仅四个扇形出生区开启 |
| `Points` | coord[] | 现有 | `s` | 可选点位集合 | 填入出生或刷新可用点位 |

出生区自动分配继续复用服务端既有规则。自由选择持续天数、KVK 期间占领时间倍率等少量全局参数，应在项目既有全局配置表中新增配置项，不为此新建专用页签；具体全局 Bean 名由研发按现有常量体系落地。

## 刷新内容依赖

| 配置 | 本功能用途 | 是否改结构 |
|------|------------|------------|

| `D2GatherCfg` | 定义资源点等级、产量、资源、范围和回收规则 | 否，调整投放 |
| `D2SearchCfg` | 定义搜索类型、半径、消耗、冷却和找不到时的创建规则 | 否，复核引用 |
| `D2MonsterCfg` | 定义野怪属性、模型、战斗和掉落 | 否，复用数据 |

# 堡垒格子与战略建筑

## `UnionWarAreaCfg`

来源：`UnionWarArea.xlsx`。该表作为新服地图堡垒格子的主配置。现有 KVK/联盟战争数据不得直接改写；所有新增字段和记录均通过 `MapType` 隔离。

### 现有字段

| 字段 | 类型 | 状态 | 读取端 | 说明 | 填表要点 |
|------|------|------|--------|------|----------|
| `Id` | int | 现有 | `cs` | 战略区域/格子 ID | 全表唯一 |
| `Level` | int | 现有 | `cs` | 格子等级 | 与出生区、中间圈、中心圈梯度一致 |
| `AreaName` | string/key | 现有 | `c` | 格子名称 | 展示文案遵循 K1 多语言规范 |
| `CoordX` | int | 现有 | `cs` | 格子中心 X 坐标 | 与地图工具坐标一致 |
| `CoordY` | int | 现有 | `cs` | 格子中心 Y 坐标 | 与地图工具坐标一致 |
| `BuildingCoordX` | int | 现有 | `cs` | 主建筑 X 坐标 | 位于对应格子可用区域内 |
| `BuildingCoordY` | int | 现有 | `cs` | 主建筑 Y 坐标 | 位于对应格子可用区域内 |
| `BuildingID` | int | 现有 | `cs` | 格子主堡垒配置 ID | 关联 `UnionWarBuildingCfg.Id`；龙巢、圣坛和王座点位由 `RandomMapUnitCfg` 配置 |

### 建议新增字段

| 字段 | 类型 | 读取端 | 说明 | 填表要点 |
|------|------|--------|------|----------|
| `MapType` | int | `cs` | 所属场景类型 | 关联 `MapTypeCfg.Id`，旧数据迁移时填入原场景类型 |
| `GridX` | int | `cs` | 格子横向序号 | 以左下角或项目既有原点为起点，整张地图统一 |
| `GridY` | int | `cs` | 格子纵向序号 | 与 `GridX` 共同唯一定位格子 |
| `ZoneID` | int | `cs` | 所属地图区域 | 关联 `D2NpcZoneCfg.ID`，用于出生区、圈层和迷雾归属 |
| `AreaType` | enum | `cs` | 格子类型 | `InitialShared` / `Normal` / `Throne` / `Unavailable`；王座实体仍由 `RandomMapUnitCfg` 投放 |
| `IsInitialShared` | bool | `cs` | 是否初始共享堡垒 | 为真时必须不可占领，但能提供首战邻接资格 |
| `IsOccupiable` | bool | `cs` | 是否可被联盟占领 | 初始共享、边界和不可用格为否 |
| `DisplayPriority` | int | `c` | 地图图标展示优先级 | 仅用于同区域图标遮挡排序，不参与服务端资格判定 |

`IsInitialShared` 是明确的玩法语义，不能仅依靠某个特殊 `BuildingID` 隐式判断。运行时联盟归属、占领进度、守军、免战截止时间不进入本表。

## `UnionWarBuildingCfg`

来源：`UnionWarBuilding.xlsx`。继续复用现有系统战略建筑对象，不新增堡垒、龙巢或圣坛对象类型。

| 现有字段组 | 本功能用途 | 填表要点 |
|------------|------------|----------|
| `Id / Type / Level` | 标识系统堡垒、龙巢、小祭坛类型和等级 | 如现有枚举不足，只扩枚举和数据，不新增平行对象表 |
| `OccupyTime / OccupySpeed / OccupyValue` | 占领时间、速度和目标值 | 普通堡垒和龙巢按主案配置 |
| `RadiusBlock / RadiusOccupy` | 建筑阻挡与占领范围 | 与 NavMesh 和格子范围校验 |
| `OpenTime / OpenTimeB` | 建筑开放窗口 | 仅用于单建筑规则；区域共享迷雾由 `FogLayerCfg` 控制 |
| `Property` | 建筑属性引用 | 关联 `UnionWarBuildingPropertyCfg` |
| `Yield / Drop / DropTimes / MaxGatherTimes` | 产出与奖励 | 按既有龙巢、祭坛规则复用 |
| `NumberLimit / LevelRequest / PowerRequest / BuildingRequest` | 数量和准入条件 | 与联盟科技上限、前置条件一致 |
| `PeaceTime / InitialPeaceTime` | 普通和首次占领免战时间 | 新联盟首战成功后的免战优先使用现有字段表达 |
| `MonsterID / MonsterLv / DropItem` | 初始守军与掉落 | 复用既有龙巢/战略建筑战斗流程 |
| `Model / DisplayKey / RecordAsset / Icon / PropertyIcon` | 客户端表现资源 | 复用既有资源，仅新增配置记录 |
| `RankScore` | 排行积分 | 按新目标口径调整投放 |

KVK 开启期内原服普通堡垒占领时间倍率属于服务器全局规则，进入项目既有全局配置体系，不在每个建筑行重复填写。

## `UnionTerritoryCfg`

来源：`UnionTerritory.xlsx`。该表继续服务旧服联盟中心要塞、远征要塞、旗帜和联盟祭坛。新服地图的系统堡垒格子不迁入该表：

- 新服模板关闭中心要塞、远征要塞和旗帜的建造入口。
- 旧服与 KVK 继续读取原有数据，不能删除或改写原类型。
- 领土保护范围在新服模板下改读已占领 `UnionWarAreaCfg` 格子集合，属于程序判定，不新增运行时配表字段。

## `KingWarBuildingCfg`

来源：`KingWar.xlsx`。王座和瞭望塔继续使用现有字段：

- `Type / OccupyTime / RadiusBlock / RadiusOccupy`：建筑类型、占领时间和范围。
- `LevelRequest / PowerRequest`：准入条件。
- `CoordX / CoordY`：新服中心王座及关联建筑坐标。
- `RecordAsset / BuffProperty / BuffValue / BuffTips`：记录资源和占领 Buff。
- 客户端模型、DisplayKey、图标继续使用现有客户端导出列。

如同一建筑配置无法同时满足旧服、KVK 与新服表现或规则，新增独立记录，并由新服专用 `RandomMapUnitCfg.BuildingID` 引用，不直接覆盖旧记录。新服王座的投放坐标以 `RandomMapUnitCfg.PositionTuple` 为准；若 `KingWarBuildingCfg` 同时保留坐标列，两处必须通过导表校验保持一致。王座开放日由 `FogLayerCfg` 的王座层级控制，王座战斗、占领、重置和奖励规则仍复用现有配置。

# 新增堡垒相邻关系表

## `FortressAdjacencyCfg`

建议工作簿：`FortressAdjacency.xlsx`。本表只表达新服地图堡垒格子的四邻攻击拓扑，不保存联盟归属或可攻击列表等运行时结果。

| 字段 | 类型 | 读取端 | 说明 | 填表要点 |
|------|------|--------|------|----------|
| `ID` | int | `cs` | 关系记录 ID | 全表唯一 |
| `MapType` | int | `cs` | 所属场景类型 | 关联 `MapTypeCfg.Id` |
| `AreaID` | int | `cs` | 当前格子 ID | 关联同 `MapType` 的 `UnionWarAreaCfg.Id` |
| `AdjacentAreaID` | int | `cs` | 相邻格子 ID | 关联同 `MapType` 的 `UnionWarAreaCfg.Id`，不可等于 `AreaID` |
| `Direction` | enum | `cs` | 从当前格子看相邻格子的方向 | 仅 `Up` / `Down` / `Left` / `Right` |
| `IsAttackPath` | bool | `cs` | 是否提供攻击资格 | 边界阻挡或特殊不可通行关系填否 |

### 导表校验

- 每条关系必须存在反向记录，且方向成对：`Up ↔ Down`、`Left ↔ Right`。
- 同一 `MapType + AreaID + AdjacentAreaID` 只允许一条有效关系。
- 相邻格子的 `GridX / GridY` 曼哈顿距离必须为 1，不允许对角或跨格配置。
- 两端必须属于同一个 `MapType`；不可用格和王座特殊格是否进入拓扑按主案规则配置。
- `IsAttackPath=false` 只关闭攻击资格，不改变 NavMesh 通行；实际行军阻挡仍由地图工具产物决定。

# 新增服务器共享迷雾表

## `FogLayerCfg`

建议工作簿：`FogLayer.xlsx`。本表维护服务器共享的区域开放计划；当前开放层级和已开放时间属于运行时状态，不写回配置表。

| 字段 | 类型 | 读取端 | 说明 | 填表要点 |
|------|------|--------|------|----------|
| `ID` | int | `cs` | 迷雾层记录 ID | 全表唯一 |
| `MapType` | int | `cs` | 所属场景类型 | 关联 `MapTypeCfg.Id`，与旧服/KVK 隔离 |
| `Layer` | int | `cs` | 迷雾层级 | 同一 MapType 内从 0 连续递增 |
| `ZoneIDs` | int[] | `cs` | 本层覆盖区域 | 关联同一新服刷新模板下的 `D2NpcZoneCfg.ID`，区域不得跨层重复 |
| `UnlockOpenDay` | int | `s` | 开服第几天开放 | 出生区为 0；中间圈、中心圈、王座按主案配置 |
| `UnlockTime` | time | `s` | 开放日的具体时间 | 使用服务器时区和项目标准 time 类型 |
| `ShowObjectModel` | bool | `c` | 未开放时是否显示对象模型 | 主案要求堡垒、龙巢、圣坛图标/模型可见时填真 |
| `HideObjectData` | bool | `cs` | 未开放时是否隐藏类型、归属和战斗信息 | 服务端不下发或客户端不展示敏感详情 |
| `BlockObjectClick` | bool | `c` | 未开放时是否屏蔽对象点击 | 填真时不进入对象详情 |
| `BlockMarch` | bool | `cs` | 未开放时是否阻止进入区域 | 服务端必须做最终校验，客户端同步拦截和提示 |

### 导表校验

- 同一 `MapType + Layer` 唯一，`UnlockOpenDay + UnlockTime` 必须随层级递增。
- 每个新服 `D2NpcZoneCfg.ID` 只能归属一个迷雾层级。
- `ZoneIDs` 对应记录的 `MapId` 必须等于该 `MapTypeCfg.NpcRefreshId`。
- 层级 0 必须覆盖全部出生区和初始共享堡垒所在区域。
- 王座层的开放时间不得早于中心圈开放时间；王座战自身活动时间仍由既有王座规则控制。
- `BlockMarch=true` 必须由服务端判定，不能只依赖客户端遮罩。
