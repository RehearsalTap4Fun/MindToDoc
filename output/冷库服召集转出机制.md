# 简介

## 设计目的

冷库关闭仍需强转兜底，但活跃玩家应尽量在关闭前完成主动转出，并通过随盟迁移或召集入盟保留联盟关系。对个人迁移和强转后无盟的玩家，继续提供落地入盟与召集补救，降低落地无盟带来的流失。

本功能以一期联盟跨服召集活动串联冷库预告、主动迁出、关闭强转和落地补救，具体阶段见「冷库流程时间轴」。

## 功能简述

- **召集市场除名**
  - 冷库服自预告开始不可发布召集、不可作为迁入目标，其玩家仍可申请其他服召集。
- **三通道承载于召集活动页**
  - 按【申请迁入】【联盟迁移】【个人迁移】排序，分别对应通道①②③，不另设独立转出页。
- **目标范围统一**
  - 三通道均沿用现行召集活动范围：同分组，当前或 +1 版本。合法可选列表中增加“推荐”标签，未获标签的目标仍可选择。
- **保留联盟关系优先**
  - 通道①申请已发布召集的联盟，审批通过后迁服入盟；通道②随联盟迁入目标服；通道③个人迁入后使用落地服现有联盟推荐与快捷入盟功能。
- **特权有明确终点**
  - 通道①成功后结束当期冷库迁移特权；经通道②③或强转落地者保留一次通道①补救机会，最晚至 D5 结束。

| 通道③ | D1–D3 个人迁入目标服 | 非盟长可用，落地后通过本服现有功能入盟 |
| 目标范围 | 同分组、当前或 +1 版本，沿用召集范围规则 | 三通道一致；资格、容量等执行校验保留 |

# 详细规则

## 全局机制

### 冷库流程时间轴

D1 为当期召集首日。D2 结束、D3 结束和 D5 结束均指相应服务器日的结束时点；联盟准备倒计时从实际发起时间计算，不按自然日取整。

| 时间 | 阶段 | 开放内容与系统行为 |
|------|------|--------------------|
| 召集前 2 天 | 预告 | 登录弹窗与邮件；三页签只读；冷库服召集除名 |
| D1–D2 | 主动转出 | ①申请召集、②发起联盟迁移、③个人迁移；已发起联盟各自倒计时 |
| D2 结束 | 联盟发起截止 | 不再接受新发起或取消后的重新发起；已发起联盟继续准备 |
| D3 | 主动转出与准备收尾 | ①③继续开放；已发起联盟满 24 小时后执行，最晚 D3 结束生效 |
| D3 结束 | 冷库关闭与强转 | 关闭③；处理到期联盟迁移，再对剩余角色执行现有强转 |
| D4–D5 | 召集补救 | 已落地且有补救资格的无盟玩家可使用①；②③关闭 |
| D5 结束 | 当期结束 | 未处理申请失效，未使用补救机会和冷库来源身份到期 |

- **时间示例**
  - D1 10:00 发起的联盟在 D2 10:00 准备结束；D2 23:00 发起的联盟在 D3 23:00 准备结束。
- **冷库来源身份**
  - 冷库服以正式冷库名单及排期为准；预告开始时所在服为冷库服的玩家获得当期来源身份，随迁移保留至 D5 结束，用于来源记录、名额归属和补救资格判断。
  - 特权与成功次数按「冷库特权与限流」判定。
- **配置生效**
  - 冷库排期与召集活动共同确定阶段时点；携带窗口、推荐统计阈值和名额规则调整于下一期生效，进行中名单不因热更重算。

### 兼容与复用

| 项目 | 处理 |
|------|------|
| 旧客户端 | 在召集活动提醒更新，更新前无法使用 |
| 转服记录 | 成功转出后照常记录现有召集及个人转服时间；当期特权结束后恢复常规冷却校验 |
| 已开始的迁移 | 预告开始前已通过待转入的申请、已进入旧流程的联盟迁移照常完成，沿用迁移中保护 |
| 联盟归属 | 名单变更见通道②「携带名单」，联盟数据沿用现有退盟与迁移规则 |
| 角色与复核 | 各通道的目标角色数、普通成员无法随盟迁移、盟长检查与执行复核失败均沿用对应现有功能 |
| 重复操作 | 申请、发起、取消、确认、退出及重连重放均返回当前最终状态，不重复占用、扣减、迁移或消耗机会 |
| 迁移中保护 | 召集、个人及联盟迁移跨过阶段结束时照常处理；失败、重试、复核及强转保护沿用现有功能，避免重复迁移 |
| 版本保护 | 版本切换前后保护窗口沿用迁服引擎，拒绝时提示稍后重试 |

## 召集市场除名

- **冷库服联盟不可发布召集**
  - 自预告开始，发布、修改与留言入口关闭并说明原因。
  - 若预告开始时仍有生效召集，立即下架；未处理申请按拒绝处理，释放名额并向申请者发送目标服务器变更邮件。
- **冷库服不可作为迁入目标**
  - 其他服的召集列表、个人迁服和联盟迁服目标列表均排除冷库服，服务端同步校验。
- **冷库服玩家保留转出方向**
  - 在本案窗口内通过召集活动页的三条通道转出，目标统一从活动可选列表选择。

## 冷库转出入口

- **页签与身份**
  - 仍在冷库服的来源玩家显示【申请迁入】【联盟转移】【个人转移】，不显示【审批】。
  - 迁出落地后恢复落地服常规【申请迁入】【审批】页签及权限；申请迁入按剩余补救资格展示内容，通道②③不随身份带到新服。
  - 非冷库来源玩家的入口不变。
- **预告段**
  - 每日首次登录弹出预告，说明关闭时间、三通道开放时间，并持续显示距 D3 结束的服务器关闭倒计时。
  - 预告弹窗提供【前往召集】按钮：D1 前置灰并提示召集活动开放后可前往；D1 开放后可点击进入召集活动主页。关闭弹窗不影响倒计时。
  - 三个页签可见但只读；展示目标预览与开放倒计时，操作提示 D1 开放。
- **申请迁入页签**
  - 展示已发布召集的可选联盟、剩余冷库名额与推荐标签；截止时间为 D5 结束。
  - 无盟且有资格者可申请；有盟者提示退盟后可申请，已用完特权者按常规召集规则处理。
- **联盟迁移页签**
  - 未发起时，盟长看到目标服列表、默认携带人数预览和距 D2 结束的发起截止倒计时；D3 不再显示可发起状态。
  - 发起后以准备信息替换目标服列表，全盟看到目标服、本盟 24 小时准备倒计时、携带人数和本人携带状态；关闭弹窗、切换页签或重新进入活动后仍显示当前进度。按权限提供取消、转移列表、退出或确认加入操作。
  - 准备期倒计时结束即进入执行状态，不再允许名单操作；无盟者提示使用①或③。
- **个人迁移页签**
  - 展示目标服、推荐标签和距 D3 结束的倒计时；盟长提示先转让盟长或使用②。
  - 联盟转移与个人转移的冷库可选目标均无需目标服审批，列表直接展示可选目标。
- **补救阶段**
  - D4–D5 对有剩余资格的无盟玩家展示召集补救与截止时间；有盟玩家显示已有联盟。
  - 本服联盟推荐与快捷入盟保持现有入口。

## 可选目标与推荐标签

### 可选服务器范围

- **三条通道统一范围**
  - 均采用现行召集活动的分组和版本限制：同分组，目标为当前或 +1 版本。版本可见性及版本切换保护按现行召集处理。
  - 目标不是冷库服、不处于禁入或维护状态，并满足现有迁入资格校验。
- **范围与执行校验分开**
  - 推荐标签不作为准入条件。各通道仍执行其名额、人数、角色上限及迁入额度检查，未获标签不等于豁免这些检查。
  - 玩家打开列表和提交操作时按当前数据校验；名额或额度不足时说明原因，不能因列表曾显示可选而承诺迁入。
- **排序与人工名单**
  - 保留合服分组映射锚服、BI 联盟推荐分与语言等现有方案排序依据；服务器侧使用相应聚合结果。
  - 运营人工名单仅优先展示合法范围内的目标，不突破同分组、版本、禁入或其他资格条件。
- **无目标的反馈**
  - 有合法目标但没有“推荐”标签时，正常展示和选择，不判定空池。
  - 没有合法可用目标时提示暂无可用目标并触发运营告警；不回退到无限制自选服，人工名单也不能绕过资格恢复通道。

### 推荐标签

可选列表增加一个“推荐”标签，以下三项同时满足才显示。标签在服务器条目展示，联盟条目承接其目标服标签；标签仅供选择参考。

| 条件 | 判定要求 |
|------|----------|
| 语言匹配 | 来源侧与目标服活跃玩家的主要语言相同，使用 BI 的语言统计与匹配口径 |
| 活跃规模 | 目标服活跃人数在 50–200 档，包含 50 和 200 |
| 付费结构 | 目标服近 30 天付费玩家比例达到健康标准 |

- **数据口径**
  - BI 提供活跃玩家、主要语言及健康比例判定；活跃统计窗口、付费比例分母和健康阈值通过 BI 口径与配置维护。
  - 标签随有效数据刷新；数据缺失无法判定时不显示“推荐”，不因此移除合法目标。

### 可选联盟范围

- **仅召集发布联盟**
  - 通道①只展示当期已发布召集、目标服合法且符合接收条件的联盟，沿用召集申请数上限；同一联盟不重复展示。
- **目标须在其他服**
  - 落地后的通道①排除当前所在服联盟，始终按跨服召集执行；本服入盟使用现有联盟推荐、申请和快捷入盟。
- **接收能力**
  - 可申请目标须有冷库来源名额和联盟空位；名额动态用尽时显示已满并阻止提交。

## 通道①：申请加入召集联盟

- **申请条件**
  - 当前处于 D1–D5，玩家有未使用的当期冷库迁移或补救资格，且当前无盟。
  - 目标联盟符合可选范围，有冷库召集名额，玩家在目标服角色数未达上限。
  - 盟内玩家须先退盟才能申请，退盟时按通道②「携带名单」处理。
- **名额**
  - 占用接收联盟单列的冷库来源召集名额，不与常规召集争抢；可用名额取接收服 DAU 档配置、接收盟人数档配置和联盟剩余空位的最小值。
  - 名额为 0 时提示冷库名额已满，可选择其他目标；②③仅在各自窗口和条件内可用。
- **审批与执行**
  - 由目标联盟 R4 及以上审批，沿用召集审批流程与日志。
  - 通过后按现有召集流程以玩家当前所在服为出发服迁入并加入目标联盟，展示入盟提示。
  - 通过后未在现有等待时限内完成转入，沿用现有失效、通知与名额释放处理；复核见「兼容与复用」。
- **成功与失败**
  - 成功转入并入盟后，清理其他未处理申请并释放相应名额；资格变化见「冷库特权与限流」。
  - 拒绝、失效或迁入失败时，按现有召集通知说明原因；重新申请资格见「冷库特权与限流」。
- **强转后的申请衔接**
  - D3 结束仍未审批的申请随强转保留，后续审批从玩家当前落地服执行。
  - 玩家落地后已入盟，或落地服恰为该申请的目标服时，取消对应未处理申请并释放名额、通知玩家。
  - 同服申请不自动转成本服入盟申请；玩家有需要时手动使用落地服现有入盟功能重新申请。
- **结束**
  - 活动结束时未处理申请失效并释放名额；已进入执行的请求按「兼容与复用」处理。

## 通道②：整盟迁入目标服

### 发起与准备

- **发起窗口与条件**
  - 仅 D1–D2 接受发起；发起人为盟长，联盟不在迁移中且仍在冷库服，目标符合三通道统一范围。
  - 按携带名单人数一次性预占目标服迁入额度；额度不足则发起失败并提示更换目标。
- **24 小时准备期**
  - 每次成功发起后准备 24 小时，沿用现行联盟迁移准备期规则；到期即锁定并执行，最晚正常生效时间为 D3 结束。
  - 发起后页签状态见「冷库转出入口」，通知见「通知与红点」；已预占额度不受后续同日迁入挤占。
- **取消与重新发起**
  - 准备期内按现有规则由盟长取消，释放预占额度、清空携带状态，取消不产生冷却；通知见「通知与红点」。
  - 重新发起须在 D2 结束前，并重新计算完整 24 小时准备期；D2 截止后拒绝新发起。D3 取消不能再发起，剩余通道按窗口使用。

### 携带名单

- **盟长管理**
  - 准备期内盟长可将其他成员移出携带名单，也可恢复携带；本人不提供移除操作。移出仅调整名单，不立即退盟；恢复时沿用迁入额度校验，成功后更新预占额度与人数。
- **默认名单**
  - 发起时近 7 天内有登录的成员默认携带，窗口可配置，不作农场号判定；窗外成员默认不带。
- **确认加入**
  - 窗外成员在本盟准备结束前登录并确认加入，额度足够则进入名单并增加预占；不足则提示无法加入，其他通道按各自窗口使用。
- **退出携带**
  - 准备结束前可退出携带，退出即退盟；退盟、被踢或个人迁走均自动脱离名单并释放对应额度。
  - 已退盟成员自主选择后续迁出方式。

### 到期执行与落地

- **锁定与执行**
  - 本盟准备结束时冻结名单，停止取消、退出和确认加入；未携带成员按名单规则退盟，通知见「通知与红点」。
  - 沿用整盟迁移流程，执行中拒绝新成员加入；迁移完成后恢复目标服联盟数据并清理原服数据。
  - 未随盟转出的角色按剩余窗口使用①③，至 D3 结束仍留在原服者进入现有强转。
- **失败处理**
  - 按「兼容与复用」处理复核失败、目标暂不可用和重试；原因与操作提示见「通知与红点」。
  - 后续改选、改派（含 D5）由玩家自主操作，并遵守对应功能的时间和资格限制。
- **落地与补救**
  - 随盟落地保留联盟归属，补救资格见「冷库特权与限流」。

## 通道③：个人迁入目标服

- **条件**
  - D1–D3 期间仍在冷库服，有当期冷库迁移资格；不是盟长，盟长须先转让或使用②。
  - 目标符合统一范围，目标角色数与迁入额度通过现有校验。
- **执行**
  - 沿用个人迁服流程，有盟者迁出时自动退盟并脱离携带名单；落地时无盟。
- **落地安置**
  - 无盟时触发现有本服联盟推荐弹窗，按现有申请或快捷入盟规则加入本服联盟；补救资格见「冷库特权与限流」。
- **关闭**
  - 按时间轴停止新迁移，进行中的请求按「兼容与复用」处理。

## 冷库特权与限流

三通道在有效资格及对应窗口内按下表享受豁免，并执行各自限流；等级豁免指城堡等级门槛，道具豁免指免费迁移、不消耗转服道具。

| 通道 | 召集名额 | 迁入总量 | 豁免 |
|------|----------|----------|------|
| ①申请召集联盟 | 单列冷库名额 | 沿用召集流程 | 等级、召集及个人转服冷却、道具 |
| ②联盟迁移 | 不占用 | 按携带人数预占 | 等级、转服冷却、道具 |
| ③个人迁移 | 不占用 | 正常计数 | 等级、转服冷却、道具 |

| 玩家状态 | 当期冷库资格 | 后续行为 |
|----------|--------------|----------|
| 尚未成功转出 | 原冷库三通道资格 | 按各通道窗口与条件选择 |
| 经①成功迁服入盟 | 当期特权结束 | 后续迁服按常规规则，退盟不重置 |
| 经②③或强转落地 | 保留一次①补救机会 | 最晚至 D5 结束，不能在新服继续用冷库②③ |
| ①申请或迁入失败 | 未消耗成功次数 | 窗口内满足条件可手动重新申请 |
| 普通本服入盟 | 不消耗①补救次数 | 入盟后不满足①无盟前置，需自主退盟才可申请 |
| D5 结束 | 身份与未用机会到期 | 恢复常规规则 |

## D3 关闭与强转

- **执行**
  - 按时间轴处理到期联盟迁移及剩余角色；进行中的迁移按「兼容与复用」保护。
  - 目标由平台按现有强转机制匹配，有盟随盟、无盟个人；未发起迁移的联盟整体强转，携带规则沿用现有功能。
- **落地后**
  - 通知见「通知与红点」；无盟玩家可使用本服现有入盟功能，或按「冷库特权与限流」使用①补救。
  - 原召集申请按通道①「强转后的申请衔接」处理。

| 联盟取消 | 全盟通知 | 取消结果及按「发起与准备」判定的重新发起资格 |
| 未携带退盟 | 个人邮件 | 联盟去向、本人未随盟及剩余可用方式 |
| 迁移失败 | 沿用现有通知 | 实际原因和现有可执行操作 |

### 红点与进行中状态

| 位置 | 触发 | 消除 |
|------|------|------|
| 召集活动入口 | 预告首次登录、D1 开放 | 打开活动页 |
| 联盟迁移页签：可发起 | 盟长有资格、未发起且未过 D2 截止 | 发起、失去资格或 D2 截止 |
| 联盟迁移页签：确认携带 | 本盟准备中，自己为可确认加入的窗外成员 | 确认、准备结束、取消或失去资格 |
| 落地服活动入口：补救 | D4–D5 无盟且有剩余①资格 | 打开申请迁入页签或失去资格 |

联盟迁移进行中角标与目标、倒计时属于持续状态展示，打开页签不消除；执行完成或取消后消除。红点由服务器按状态计算，沿用召集入口冒泡规则。

## 边界情况

通道内的截止、名单变更和强转申请分支见对应详细规则；跨阶段迁移及重复请求见「兼容与复用」。

| 场景 | 处理 |
|------|------|
| 申请后目标进入冷库预告或失去现有接收资格 | 申请失效、通知并释放名额 |
| 迁移中转让盟长 | 沿用现有迁移中禁止转让规则 |
| 目标服 DAU 档在发起后变化 | 已预占额度沿用现有预约保障，新发起和新增携带按当前可用额度校验 |
| 服务器维护跨 D3 结束 | 恢复后按原到期时间处理到期任务与强转，不顺延至下一期 |

## 效果指标

以既有《跨服召集转服分析》为历史对照，正式基线与统计口径由 BI 维护。本次重点观察迁出方式、落地入盟与后续留存，推荐标签命中率不替代迁入与留存效果。

| 指标 | 观察方向 |
|------|----------|
| 冷库活跃玩家随盟或召集入盟落地比例 | 提升 |
| 活跃玩家被强转比例 | 下降 |
| 强转活跃玩家第 4 周留存与对照差距 | 缩小 |
| 召集拉入后续关闭服的人次 | 下降 |
| 联盟迁移发起数、携带人数与成功率 | 观察主动迁出规模与失败原因 |
| ①补救申请、通过与实际入盟率 | 观察一次补救机会的安置效果 |
| ③及强转落地后的本服入盟率与留存 | 观察本服推荐与快捷入盟效果 |
| 推荐标签目标的选择率、迁入率与留存 | 对比无标签目标，验证推荐有效性 |

- **记录维度**
  - 区分①②③、强转及落地后①补救；记录阶段、来源与目标服、是否合服锚服、是否有推荐标签。
- **失败与资格记录**
  - 区分名额已满、迁入额度不足、目标不可用、角色上限、窗口结束和状态变化；记录同服申请取消及特权成功消耗。
- **后续去向**
  - 观察未携带退盟成员、个人迁移与强转无盟玩家的后续入盟及留存。
