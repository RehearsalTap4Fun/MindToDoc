# 策划精简判断梯

用于起草前的范围收口，以及对策划案做精简、压缩、去重、删减、派生物或过度设计审查。目标是减少无评审增量的内容，不是追求最短文档。

## 精简风险分级

压缩率是结果指标，不是继续删减的完成条件。默认从低风险层开始，命中停止条件后不得为了得到更高比例自动升级：

| 层级 | 允许动作 | 进入条件 |
|---|---|---|
| L1 零规则改写 | 删除完全重复副本；复用已经存在且已核验的派生文档 | 默认执行 |
| L2 结构精简 | 合并同义规则；改为多级列表、表格或流程图；唯一 SSOT 外只留摘要 | L1 后仍有明确重复，且能逐条证明语义无损 |
| L3 语义压缩 | 改写规则措辞或缩短流程节点，但不改变任何业务原子 | 用户明确要求进一步压缩，并完成源规则覆盖矩阵 |

用户给出量化目标时，目标只用于报告实际结果与差额。正文减少达到或超过 40%，或准备进入 L3 时，一律按高风险精简处理：必须逐条建立覆盖矩阵；覆盖未闭环时不得给出“安全精简”结论。

量化统一使用精简前后同一统计范围：取主案正文首尾去空白后的 Unicode 字符数和物理行数；空行、表格行、代码块与 Mermaid 行均计入行数，派生文档不并入主案正文。若工具或平台只能提供其他口径，报告必须注明，不能与本口径直接比较。

## 审查前门禁

1. **锁定基线**：确认权威源、版本号、更新时间和本期变更记录；本地与在线版本不一致时先选择审查基线，不得拿旧快照覆盖新规则。
2. **拆成业务原子**：混合段先拆成 `主体｜触发｜条件｜动作｜分支｜反馈｜重置/恢复｜异常`，再逐项打标签。同一段中的机制规则、玩家行为、视觉参数和实现证据不得共用一个标签。
3. **标记冲突**：两个来源给出不同确定口径时标为 `clarify`，同时保留双方证据；精简过程不得替规则负责人任选其一。
4. **验证迁移闭环**：`relocate` 只有在目标文件存在、具体章节明确、内容已经落入且版本一致时才算完成。任一条件不满足，源内容继续 `protect`，不得从精简稿删除，也不得计入已迁移；报告的“动作”统一写为“暂时保留；建议移动到派生文档：<文件名或文档类型>。”
5. **锁定媒介职责**：流程图若声明为流转 SSOT，必须保留所有成功、失败、取消、回退、恢复和终止边；若只保留主干，则改称摘要并引用完整规则落点。
6. **分离版本层次**：详细规则只写当前最终状态；“从 A 改为 B”的过程只写变更记录。只有旧数据、老客户端或旧配置在上线后仍可能出现，并且文档定义了识别条件与处理结果时，才作为兼容规则保留。

## 判断梯

对每条规则、章节、表格和计划创建的派生文档依次判断，命中即停止：

1. **本期范围**：是否属于用户已确认的本期目标？不属于则从本期交付物删除；只有用户明确要求追踪时才记录到后续范围。
2. **已有来源**：主案、派生文档、reference、公共配置或既有系统是否已有可复用结论？有则引用或复用，不重新定义。
3. **文档归属**：内容是否属于功能规则？技术实现、配置字段、控件表现、资源清单、排查证据迁移到对应派生文档。
4. **事实依据**：是否有创建内容所需的真实素材或业务目标？无截图不创建界面标注，无音频需求不创建音效需求，无分析目标不创建 BI 日志需求。
5. **唯一 SSOT**：是否与其他位置重复？关键决策只留摘要，详细规则只保留一个唯一落点，其他位置引用该落点。
6. **无损合并**：能否合并表达且仍保留触发条件、状态分支、不满足提示和结果反馈？可以则合并。
7. **成稿残留**：是否只是占位符替换、换图提醒、正文已经落实的示例/术语纠错，或在详细规则重复“旧规则已废止/现已改为”？已完成则删除；未完成则进入界面标注或交付 Checklist。仍影响计算的语义并入对应参数或机制定义，不单独成条。实际版本变化只在变更记录保留一次。
8. **最小新增**：前述均不成立时，才新增满足评审所需的最小内容。

流程图、表格与文字表达同一结论时，不按媒介机械删减：选择最能承载完整分支的形式作为详细 SSOT，另一处只留摘要或引用。

## 保护项

以下内容不得为了达到字数、页数或文件数量目标而删除：

- 设计目的、核心循环和关键决策。
- 触发条件、状态分支、不满足提示和结果反馈。
- 跨系统边界、异常情况、重复请求、活动结束和维护状态。
- 老客户端、转服、热更、幂等、KVK 往返等数据兼容规则。
- 玩家体验、物理语义、数值曲线等设计意图。
- 生成、随机、分配、轮换、耗尽重置、自动恢复等决定系统如何运行的机制规则；它们引用的参数或资源可以迁移，机制本身不能随参数一起删除。
- 玩家可感知的系统行为，如自动打开、能否进入流程、强制跳转、确认/取消结果；控件位置、样式和动效可进入界面标注。
- K1 项目中直接驱动业务分支的关键常量关联（语义名称 + 已知常量 ID）。
- 仍可能遇到旧数据、老客户端或旧配置的兼容规则；必须保留识别条件、迁移/降级动作和最终结果，不能因出现“旧/原”字样而机械删除。
- 用户明确要求保留的内容、版本记录和决策追溯。

若安全精简后仍未达到量化目标，停止继续删除保护项；报告实际结果与差额，由用户决定是否将一个完整的非核心范围延期。

## 审查标签

| 标签 | 判定 | 动作 |
|------|------|------|
| `delete` | 空节、失效内容、无变化映射、纯格式噪音或详细规则中重复的版本过程说明 | 删除，不设置替代内容；历史只保留在变更记录 |
| `reuse` | 既有系统、规则、公共配置或文档已经覆盖 | 引用现有来源，不重新定义 |
| `merge` | 同一结论在多个位置重复 | 合并到一个详细 SSOT，其他位置留摘要或引用 |
| `relocate` | 内容有效、文档归属错误，且目标文件存在、内容命中、版本一致 | 迁移到已存在的具体章节；只有闭环后才从源文档移除并计入已迁移 |
| `clarify` | 模糊表述、来源冲突或缺少规则负责人拍板 | 保留冲突证据并继续澄清；真未定项注明拍板人 |
| `protect` | 命中保护项，或候选派生文档尚不存在/未实际承接内容 | 保留；只允许无损改写。若归属应调整，在报告注明“暂时保留；建议移动到派生文档：<文件名或文档类型>。” |

标签描述的是审查动作，不代替规则判断。同一项只给一个主标签；若命中 `protect`，不得同时标为 `delete`。

## 输出契约

精简或派生物审查按以下顺序输出：

1. **结论**：能否安全达到目标；计划创建、复用或拒绝创建哪些交付物。
2. **审查表**：逐项填写 `位置｜标签｜动作｜唯一落点｜理由`。`唯一落点` 必须是具体章节、派生文档或现有来源；`delete` 可写“无”。候选派生文档不存在或未命中内容时，标签必须为 `protect`，唯一落点仍写当前源章节，动作统一写“暂时保留；建议移动到派生文档：<文件名或文档类型>。”
3. **迁移核验**：逐项填写 `源位置｜目标文件｜目标章节｜存在性｜内容命中｜版本一致`；未闭环项不得计入已迁移。
4. **保护项**：列出本次明确保留的规则，避免字数压力覆盖设计完整性。
5. **源规则覆盖矩阵**：高风险精简逐条填写 `源规则原子｜处理标签｜精简后落点｜语义核对｜状态`。只有全部状态为“已覆盖”才允许给出安全结论。
6. **汇总**：统计删除、复用、合并、迁移、澄清、保护及拒绝创建的数量；量化压缩任务同时报告实际结果与目标差额。

时间不足不能豁免门禁。若审查未完成，只交付“已审范围、未覆盖范围、当前测量值和阻断项”的阶段报告，不得把部分覆盖写成安全精简结论。

不要用总字数作为唯一质量指标。至少同时检查重复规则、错位内容、空章节、无依据派生文档和保护项完整性。

### 快速示例

| 位置 | 标签 | 动作 | 唯一落点 | 理由 |
|------|------|------|----------|------|
| 联盟染色 Hex 表（目标文档不存在） | `protect` | 暂时保留；建议移动到派生文档：`-界面标注.md` 或颜色配置。 | 当前主案“联盟染色” | 属于视觉参数，但迁移尚未闭环 |
| 联盟染色 Hex 表（目标已存在且内容命中） | `relocate` | 从主案移出并引用目标章节 | `-界面标注.md` 或颜色配置的具体章节 | 目标文件、章节、内容和版本均已核验 |
| 联盟首次占领抽色与色池耗尽重置 | `protect` | 保留触发、不放回随机和重置循环 | 主案“联盟染色” | 属于业务机制，不能随 Hex 参数迁出 |
| 最高 LOD 自动打开缩略地图 | `protect` | 保留玩家可感知的自动打开行为 | 主案“缩略地图” | 控件样式可迁移，系统行为不可删除 |
| 迷雾未开放时禁止行军 | `protect` | 保留业务结论 | 主案“迷雾系统” | 影响玩家行为与系统判定 |
| 详细规则“前 2 名发奖；原仅第 1 名规则废止”中的后半句 | `delete` | 删除重复历史说明 | 无（变更记录已覆盖） | 详细规则只需写当前前 2 名发奖 |
| 旧任务已投放时热更替换或隐藏并补偿 | `protect` | 保留触发、处理和补偿结果 | 主案“兼容与边界” | 是上线后仍会执行的迁移规则，不是历史说明 |
| 无音频素材的音效需求 | `delete` | 不创建派生文档 | 无 | 缺少事实依据，空文档无评审价值 |
