# 2026世界杯主题活动开发文档评审

**评审日期**：2026-06-02
**评审对象**：`output/2026世界杯主题活动-开发文档.md`
**评审范围**：文档严谨性、完整性、可开发性、原型覆盖度、与输入素材的一致性。

## 结论

当前样例文档结构完整度较高，已覆盖原始输入中的主要系统，并且每个系统基本都包含规则、流程图、界面原型链接和数据表。它适合作为系统设计初稿或策划评审稿。

但距离“程序可直接按表开发”还有缺口。主要风险集中在核心玩法边界、数据配置粒度、进度保存、结算口径和关键原型交互状态。建议优先补齐训练关卡、切片实例配置、操作模式口径、关卡保存/奖励结算、淘汰赛演算闭环。

## 主要问题

### P1 训练关卡被核心流程依赖，但没有独立规格

- 位置：`output/2026世界杯主题活动-开发文档.md:14`
- 位置：`output/2026世界杯主题活动-开发文档.md:288`
- 位置：`output/2026世界杯主题活动-开发文档.md:890`

文档把训练纳入养成循环，说明训练等级来自训练关卡，并在联调清单里要求训练关卡复用切片核心。但全文没有训练关卡的规则、消耗、奖励、失败处理、数据表和原型。

建议新增一个“训练关卡”系统，或至少在 3.4 球星养成内补齐训练关卡配置表、结算表、入口规则和奖励规则。

### P1 操作模式规则前后冲突

- 位置：`output/2026世界杯主题活动-开发文档.md:18`
- 位置：`output/2026世界杯主题活动-开发文档.md:33`
- 位置：`output/2026世界杯主题活动-开发文档.md:111`

全局规则写“玩家在每个切片自主选择”，创角试训也写每个切片可自主切换，但切片操作核心又写“同一关卡确定模式后，关卡内不可更改”。这会直接影响 UI、状态机、教学流程和关卡存档。

建议明确三点：

- 正式关卡是否首个非守门切片锁定操作模式。
- 试训是否作为例外，允许每个切片单独切换。
- 失败回溯后是否允许改操作模式。

### P1 切片配置粒度不足，开发无法真正落表

- 位置：`output/2026世界杯主题活动-开发文档.md:160`
- 位置：`output/2026世界杯主题活动-开发文档.md:168`
- 位置：`output/2026世界杯主题活动-开发文档.md:252`

`level_config.slice_list` 引用的是 `slice_type_config` 实例，但 `slice_type_config` 实际只是类型表。各切片参数也停留在文字描述，没有承载每个切片实例的球员坐标、门将权重、可操作夹角、目标点、视角、AI override 等字段。

建议新增 `slice_instance_config`，区分“切片类型定义”和“关卡中的切片实例”。公共字段与 6 类切片差异字段需要拆开。

### P2 关卡进度保存不是数值 TODO，而是产品和技术决策

- 位置：`output/2026世界杯主题活动-开发文档.md:205`
- 位置：`output/2026世界杯主题活动-开发文档.md:257`
- 位置：`output/2026世界杯主题活动-开发文档.md:874`

文档把重进是否扣门票、是否保存进度标成待定。这个决策会影响断线恢复、重复刷奖励、防作弊和客服补偿，不能只放在数值 TODO 里。

建议明确 MVP 默认规则：

- 关卡开始即扣门票，还是结算时扣门票。
- 中途退出是否保留切片进度。
- 重复进入是否可再次结算奖励。
- 断线、杀进程、后台超时如何处理。

### P2 淘汰赛演算模型仍不够闭环

- 位置：`output/2026世界杯主题活动-开发文档.md:462`
- 位置：`output/2026世界杯主题活动-开发文档.md:505`
- 位置：`output/2026世界杯主题活动-开发文档.md:521`

演算模型定义了评分、切片数和成功期望，但没有说明如何从切片成功生成比分、双方切片数不同时如何结算、平局如何破、轮空如何入结果表。配置表里还同时用 N 表示队伍人数和轮次数，容易造成歧义。

建议补充 `match_simulation_rule`，明确：

- 切片成功如何映射为进球或比分。
- 双方切片数量不一致时如何比较。
- 平局加时或点球规则。
- 轮空场的 `winner`、`score`、`replay_data` 记录方式。
- 失败队伍名次判定和奖励档位。

### P2 赛季目标中的“排名达标”存在结算时机风险

- 位置：`output/2026世界杯主题活动-开发文档.md:394`
- 位置：`output/2026世界杯主题活动-开发文档.md:632`

积分赛写玩家完成大关卡时判断合同赛季目标，排名系统又写赛季榜按大关卡结算。如果玩家先完成大关卡，其他玩家之后仍可能改变全服排名，导致“排名达标”奖励是否立即发放不稳定。

建议明确排名目标采用哪一种口径：

- 玩家完成大关卡时的排名快照。
- 赛季全服结算时的最终排名。
- 两者都存在，但奖励类型不同。

### P3 HTML 原型偏静态线框，交互验收能力不足

- 位置：`output/prototypes/bp-shop-gift.html`
- 位置：`output/prototypes/slice-operation.html`
- 位置：`output/prototypes/betting.html`

所有原型文件都存在，但整体偏静态展示，基本没有交互脚本。`bp-shop-gift.html` 同时承载 BP、商店、礼包三个系统，文档虽然标了页签，但原型没有真实切换逻辑。

建议至少补齐关键交互状态：

- BP / 商店 / 礼包 tab 切换。
- 切片操作模式切换、守门模式、回溯弹窗。
- 竞猜选中队伍、投注输入、已下注状态。
- 商店币不足、达限购、购买成功反馈。

## 完整性评价

已覆盖：

- 创角与新手引导
- 切片操作核心
- 基础关卡
- 球星养成
- 积分赛
- 淘汰赛
- 竞猜
- 排名
- BP 通行证
- 兑换商店
- 礼包

主要缺失：

- 训练关卡作为养成来源没有规格化。
- 局外道具资产体系没有独立定义，当前散落在关卡、BP、商店、礼包中。
- 切片实例配置不足，无法支撑关卡制作。
- 关卡重进、断线恢复、奖励幂等没有明确规则。
- 排名、合同目标、活动周期之间的时间口径需要统一。

## 建议改进顺序

1. 补“训练关卡”模块，明确训练入口、切片复用、训练星产出、失败/重试和数据表。
2. 统一操作模式口径，区分正式关卡、试训、回溯后的模式选择规则。
3. 新增 `slice_instance_config`，让关卡能按实例配置切片。
4. 明确关卡进度保存、重进扣门票、奖励重复领取和断线恢复。
5. 补齐淘汰赛演算闭环，包括比分、平局、轮空、名次和奖励。
6. 明确赛季排名目标结算口径。
7. 提升关键 HTML 原型交互能力，至少覆盖 tab、选择、确认、置灰和弹窗状态。
