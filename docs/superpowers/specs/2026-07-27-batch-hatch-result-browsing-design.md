# 巨龙培育二期：批量收取孵化结果浏览设计

## 背景

自动孵化会在待收取池中累积多只已孵化幼龙。二期增加批量收取后，需要继续复用一期单只孵化成功弹窗，同时避免为每只幼龙连续叠加多个结果界面。

本规则覆盖原策划案中“待收取结果仅逐个领取、不新增一键领取”的限制。

## 目标

- 玩家一次操作完成全部待收取幼龙的领取。
- 领取完成后复用现有孵化成功弹窗，逐只浏览本批幼龙结果。
- 玩家可随时结束浏览，不需要逐个关闭结果界面。

## 交互方案

采用“批量完成、逐个浏览”方案：

1. 玩家在待收取池点击“批量收取”。
2. 系统完成本批全部可领取幼龙的领取，并按待收取池当前排序从前到后生成固定的结果列表。
3. 打开现有孵化成功弹窗，默认展示结果列表中的第一只幼龙。
4. 弹窗底部展示“下一个”和“确认”两个按钮：
   - 点击“下一个”：在同一个弹窗内切换为下一只幼龙的头像、特性、兵种和成长值信息，不重复执行领取。
   - 点击“确认”：立即关闭本批全部结果展示，返回待收取池界面；尚未浏览的结果不再补弹窗。
5. 展示到最后一只幼龙时隐藏“下一个”，仅保留“确认”。
6. 本批只有一只幼龙时，弹窗首次打开即只展示“确认”。

## 界面调整

- 沿用现有孵化成功弹窗的背景、标题、幼龙头像、特性、兵种和成长值信息区。
- 原底部单按钮区域调整为双按钮区域：左侧“下一个”，右侧“确认”。
- 最后一只或仅有一只结果时，不保留空白的“下一个”按钮位；“确认”按钮回到原单按钮的居中布局。
- 不新增页码、左右箭头、滑动切换或循环浏览。
- 配图单独制作一张 1080×1920 界面示意，不与待收取池或其他调整点拼图。

## 状态与异常处理

- 批量领取提交前，统一复用一期龙栏容量与结果有效性校验。
- 校验失败时不打开结果弹窗，待收取结果保持原状，并展示一期对应失败提示。
- 批量领取成功后，幼龙已正式进入龙栏；关闭结果展示不会撤销领取。
- 浏览期间断线、重登或强制关闭客户端，不重复领取，也不强制恢复未浏览的结果弹窗。
- “下一个”和“确认”点击后立即锁定当前按钮，待切换或关闭完成后再响应，防止连续点击跳过多只或重复关闭。

## 验收标准

- 两只及以上结果时，第一只至倒数第二只均显示“下一个”和“确认”。
- 点击“下一个”只替换当前弹窗的幼龙展示内容，弹窗数量始终为一个。
- 最后一只不显示“下一个”。
- 任意一只结果上点击“确认”均关闭整批结果展示。
- 单只结果不显示“下一个”。
- 批量领取不会重复写入守护龙，也不会因玩家提前确认而丢失未浏览幼龙。
