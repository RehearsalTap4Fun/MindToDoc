## 结论

这次手动精简主要删掉了外围说明、设计论证、投放模块和部分通用规则，明显改善了开头与目录。但最集中的重复源——“特技清单＋四节点逐条说明”——仍然保留。

下一轮最有效的动作是让每条特技只有一个完整定义位置：把清单升级为完整规则表，公共机制集中写，特技行只写效果差异与独有例外。只删除“定位”“结束”“战报”等标签，会缩短版面，却不会消除重复定义。

## 三、已经暴露的残留和冲突

这些问题应先收口，再进一步精简。这里不替你作业务决定。

### 1. 一节点一条与三条顺次触发冲突：修改前已有

“生效规则”从主将、第一副将、第二副将中为该节点选取特技，“战后节点”也写了每节点只生效一条；但战中仍写三条特技按护身、重整、雷霆顺序触发，重整后还判断雷霆，护身定位还写给重整、雷霆争取窗口。追击同样写了斩杀、压制、整队顺次触发。

建议以已写明的每节点一条为整理方向：只判定本节点选中的那条；跨节点交互照常保留。删除同节点三条联动之前需要确认此规则口径，不能把它算成无损去重。“战后先凯旋再授予”的多条处理顺序同样需核对。

### 2. 结算步骤引用失效：本轮修改产生

现稿仅四步，减伤为第 2 步、阈值为第 4 步；战阵、压制、坚守仍引用第 3 步，战中、追击仍引用第 6 步。建议统一改为“减伤阶段”“阈值判定阶段”，降低后续增删步骤时的维护成本。

### 3. 引用目标已删除或改名

- “术语与基数”仍写“回合：见回合计量”，但回合计量已删除。
- 多处仍引用“数据兼容总则”，但该节已删除；现有“数据兼容与边界情况”并未完整承接迁服、默认值、等级上限下调等规则。
- 边界表引用“每节点一条”，该标题已改为“生效规则”。

建议回合、冷却各恢复一小段必要机制；数据兼容保留一张短表。无需恢复原先的长篇论证。

### 4. 等级与累计投入缺定义

“等级规则”空置，但升级校验、橙色分解仍依赖等级与累计投入。初始等级、上限、升级改变哪些参数、消耗计算与投入记账需要有唯一说明。五档示例可以移走；“按真实消耗累计记账，分解返还该投入”不能随示例一起消失。

“存量数据：纯新增，不影响原秘宝”也不足以替代现存规则：仓库段明确要求给已有橙色实例初始化基础碎片价值。

### 5. 已删除模块仍有尾部要求

产出与投放整章删除，但真实交战定义、边界表、待确认项仍提掉落保底、赛季上限、联盟礼物顺延。需要区分“本期取消投放改造”还是“投放另处定义”；前者清理对应尾项，后者保留准确引用。目前不能只凭删除推断。

### 6. 部队预览与仓库流程版本不一致

独立“部队特技”入口说明已删除，但战报与提示、升级成功、主副将覆盖、连战窗口失效仍要求部队预览显示或刷新。需逐项明确有效展示位置；地图部队信息是否保留应单独判断。

本地《秘宝时序特技-界面标注》已写“复用现有背包，选择与分解确认在同一弹窗”，线上主案仍是“秘宝仓库选中→打开分解确认弹窗”。这是版本冲突，本报告只标记，不自动决定用哪份覆盖。

### 7. 时序叙述可能误导：修改前已有

“四节点依次经过”“互不重合”与按双方兵力阈值触发并不必然一致：优势方可能先达到敌方追击条件，而自己从未达到战中条件。建议明确为四类触发条件；只有真实需要先后约束时才写顺序。

## 四、12 条特技各自真正需要留下的差异

以下不是新的完整规则，而是合并进一张定义表时的核对清单。通用结算、叠加、取整、战报不再在每条复写。

| 特技 | 必须保留的独有信息 |
|---|---|
| 先声 | 本场前 N 回合增伤；明确作用伤害范围；与乘胜及现有增伤的合并方式由公共规则统一定义 |
| 战阵 | 本场前 N 回合自身减伤 |
| 救护 | 本场前 N 回合，按每次新产生伤兵回战；单次不足 1 人不回战、不累计 |
| 雷霆 | 我方阈值；基数为本场损失兵力，扣除已回战部分；我方已全灭不结算；伤害不超过敌方剩余兵力 |
| 护身 | 我方阈值；下一回合开始免疫 N 回合；免疫全部伤害但我方攻击照常 |
| 重整 | 我方阈值；按触发时本场伤兵回战；无有效伤兵仍消耗本场触发机会 |
| 斩杀 | 敌方阈值；基数为敌方当前剩余可战兵力；被免疫仍算已触发 |
| 压制 | 敌方阈值；降低敌方全部伤害，包括普攻、反击、一次性伤害；持续至本场结束 |
| 整队 | 敌方阈值；按触发时我方本场伤兵回战；无有效伤兵仍消耗触发机会 |
| 乘胜 | 真实交战胜利后授予；作用于窗口内下一场前 N 回合；进入即消耗，授予场与生效场分别记战报 |
| 坚守 | 真实交战有胜负即可授予，但需有存活部队；下一场前 N 回合减伤 |
| 凯旋 | 真实交战胜利后、本场伤兵入医院前就地恢复；剩余伤兵照常入医院；恢复兵力计入下一场开战兵力 |

这里最容易误删的是：雷霆用损失兵力、斩杀用剩余兵力；救护用每次伤兵、重整与整队用累计伤兵；护身下一回合起效；坚守失败存活也可授予。它们都不是重复参数。

## 五、精简示例

下面演示“公共机制一次＋特技差异一行”的写法，不构成可直接替换的完整定稿。

**开战节点公共规则：**战斗建立后，从第 1 回合起生效 N 回合，结束后失效；免疫期间照常计数。同部队与同一目标在接战冷却内再次交战时不触发。N 及效果比例按特技等级配置。

| 特技 | 效果 | 独有补充 |
|---|---|---|
| 先声 | 生效期间，普攻及雷霆、斩杀的伤害提高 A% | 增伤合并方式见公共结算规则 |
| 战阵 | 生效期间，受到的伤害降低 A% | 减伤相加、上限及免疫优先见公共结算规则 |
| 救护 | 生效期间，每次新产生的伤兵按 A% 立即回战 | 向下取整；不足 1 人不回战、不累计；已回战部分从伤兵中扣除 |

**战报公共规则：**记录生效特技名称、等级、生效回合及实际影响值；影响值按增伤、减伤、免疫、回战／恢复分类定义。未触发不显示。跨场效果分别记录授予与实际生效。各效果的战报列只填所属类型，不再写一段同义解释。

**参数表达：**主案保留 A、N 分别代表什么、按哪个基数计算、哪些维度随等级变化。15%／20%／25% 等整列示例集中到一处；在新位置完整承接前，不直接删除原有曲线。

建议最终章节压为：简介与关键决策、公共战斗机制、12 条特技定义、战报、升级、仓库与分解、装备、红点、兼容与必要待定项。四个节点不再各自承载一套重复的“定位—效果—结束—交互—等级—战报”模板。
