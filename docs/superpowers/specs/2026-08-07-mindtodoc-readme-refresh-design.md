# MindToDoc README 全面刷新设计

**日期**：2026-08-07  
**状态**：已完成对话确认，待用户书面复核

## 目标

把根目录 `README.md` 全面刷新为面向首次使用 MindToDoc 的策划与协作人员的项目入口文档。README 应能支持首次上手，同时把详细规则继续留在 `SKILL.md` 与 `references/` 中，避免重复维护和规则漂移。

## 读者与使用模型

- 主要读者：首次使用 MindToDoc 的策划与协作人员。
- 主要入口：在 Codex 中使用 `mindtodoc` Skill，而不是把仓库包装成独立命令行程序。
- 辅助脚本：Python 依赖只服务于钉钉转换、检查和表格处理等辅助能力。
- 工作区：`input/` 与 `output/` 是随当前任务变化的动态目录；稳定案例归档在 `examples/`。

## README 信息结构

1. **项目简介**：一句话定位和适用场景。
2. **核心能力**：素材整理、规则澄清、主案生成、按需派生、精简审查和钉钉同步。
3. **快速开始**：准备素材、触发 Skill、逐项确认、审核产物和归档。
4. **产物与边界**：说明主案、配置表结构、界面标注及其他派生物的职责。
5. **工作流程**：用精简阶段说明从输入到归档的数据流。
6. **目录结构**：准确描述当前目录职责，并注明动态工作区。
7. **关键原则**：单一 SSOT、一个完整功能一份主案、派生物按需创建，以及边界与兼容规则的保护要求。
8. **示例项目**：只列稳定归档案例，不罗列当前 `output/` 文件。
9. **依赖与辅助工具**：说明 Python 依赖和常用脚本用途。
10. **维护与协作**：说明同步、提交和权威规则入口。

## 快速开始设计

README 提供可直接参考的自然语言触发示例：

> 使用 `mindtodoc`，读取 `input/` 中的素材，先逐项澄清规则，再生成主功能案和确有依据的派生文档。

随后说明流程：

1. 把脑图、框架文档、参考资料或既有开发文档放入 `input/`，也可直接指定文件。
2. 在 Codex 中触发 `mindtodoc`。
3. 逐项确认功能定位、参考玩法、关键决策、模块范围与交付物。
4. 审核 `output/` 中的主案和按需派生文档。
5. 有截图时再走界面标注；需要时再同步钉钉。
6. 项目完成后归档到 `examples/<项目名>/`。
