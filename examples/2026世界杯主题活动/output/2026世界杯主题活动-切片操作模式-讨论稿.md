## 一、划线模式 · 完整骨架

### 1.1 交互流程

| 维度 | 决策 |
|------|------|
| 起手区 | 扇形（足球为顶点、控球球员高度地面投影）内任意点 |
| 落点约束 | clamp 到扇形含外延边界内 |
| 离屏语义 | 离屏点在扇形内 = 出脚；离屏点在扇形外 = 取消 |
| 拖动预览 | 实时按固定间隔刷新（节流），抬手再刷一次 |
| 重画 | 按住不放任意重画，无次数限制；结束点跟随手指 |

### 1.2 弧度输入（路径 → 飞行弧）

| 维度 | 决策 |
|------|------|
| 路径与出脚对齐 | 玩家路径整体平移到"足球→落点"基线上（形状/方向/垂距不变） |
| 偏移提取 | 提取路径相对基线的最大垂距 Δ 与方向，重新构造单条二次贝塞尔 |
| 量化 | Δ 取绝对垂距（按 dpi 换算物理距离）映射为水平转弯量 |
| 上限 | Δ 超过阈值后被 clamp，预览与实际同步表达上限 |
| S 形路径 | 取"基线绝对偏移最大"那一侧作为主弧，另一侧忽略 |
| 方向语义 | 方向只决定水平面上的转弯方向；高度/抛物线由起点-落点自动算出，玩家不可控 |

## 二、弹弓模式 · 完整骨架

### 2.1 交互流程

| 维度 | 决策 |
|------|------|
| 起手区 | **必须从足球图标上**按下（与划线区分的体感锚点） |
| 拖动语义 | 终点 = 拉弓点；出脚方向 = 球→拉弓点的反向延长线 |
| 力度输入 | 拉弓距离（连续量）映射力度 |
| 离屏判定 | 出脚方向（拉弓反向延长线）落在扇形（含外延）内 = 出脚，外 = 取消 |
| 力度超限 | 拉弓距离超最大后 clamp，可继续拖无效果 |
| 预览 | 实时按固定间隔刷新轨迹/落点；抬手再刷一次（与划线同构） |
| 重画 | 按住不放任意重画（与划线同构） |

### 2.2 高度与弧度规则

| 维度 | 决策 |
|------|------|
| 高度生成 | 仅由力度推出：力度 → 仰角 θ + 球速 v，单调递增 |
| 力度-距离关系 | **距离有上限**：超过临界力度后距离不再增加，仅高度继续上升（拉满 = 高调高球，越过门框） |
| 水平弧度·静态接球 | 水平面纯直线，无弧 |
| 水平弧度·动态接球 | 出球水平方向 = 拉弓反向 ⊕ 球员速度向量（合成系数由配置表定义） |
| 预览要包含 | 抛物线高度（v, θ）+ 动态接球时的弧度合成 |

> 隐含心智模型：高级玩家会避免拉满——拉到适中距离最远，拉满反而被吊起来不进。

## 三、模式锁定规则 · 推翻重写

### 3.1 主案旧规则（要修订）

主案"关键决策"行写："正式关首切片选定后整关锁定，守门强制划线，仅试训例外"。

### 3.2 新规则

| 切片类型 | 默认模式 | 玩家可改？ |
|----------|----------|-----------|
| 守门 | **永远强制划线** | 否（独立于本规则） |
| 任意球 | **进入时强制重置为划线** | 是（手动可切弹弓） |
| 进攻 / 点球 / 角球 / 界外球 | 沿用本关上一切片的玩家选择 | 是（随时可改） |
| 首切片 | 由配置定义初始默认（一般为划线） | 是 |
| 试训 | 不适用本规则，每片独立切换以触发对应教学 | — |

### 3.3 切换代价

**切换 = 仅重置当前预览与输入；不重载场景、不计回溯、不扣道具**。

> 隐含约束：配置表必须做到"两种模式在同一切片上难度大体相当"，切换不能成为作弊路径。这一点会在"难度平衡"节展开。

## 五-A、难度平衡与系统辅助

### 5A.1 双模式难度平衡基调

**不对齐、明显偏向**。各切片类型在两种模式下的命中率差异**故意保留**，由配置表设定偏向方向。

| 切片类型 | 偏向模式 | 偏向理由 |
|---------|---------|---------|
| 进攻 | 均衡（无明显偏向） | 通用切片，需双模式都能玩 |
| 任意球 | 划线明显更优 | 绕墙画弧是经典手感，弹弓静态接球无法表达弧 |
| 点球 | 弹弓略优 | 弹弓"鱼跃"手感与真实点球踢法贴近，划线在小扇形里画弧意义弱 |
| 角球 | 划线明显更优 | 弧线传中是核心打法，弹弓静态无弧、只能直传或冲门 |
| 界外球 | 取决于扇形大小 | 配置决定 |

**心智模型**：玩家在"切换零代价"的机制下会自然学会"什么切片用什么模式"——这是 feature 不是 bug。两种模式各有高光场景，避免一种模式被完全淘汰。

### 5A.2 系统辅助 · 辅助线表现

| 项 | 决策 |
|----|------|
| 辅助线内容 | **只画足球完整运行轨迹与落点**，不提示门将扑抢范围 |
| 划线模式预览 | 玩家拖动路径同步刷新轨迹与落点（节流） |
| 弹弓模式预览 | 拉弓力度变化时同步刷新抛物线高度与落点（节流） |
| 抬手刷新 | 抬手瞬间额外刷新一次预览，确保最终态准确 |
| 门将信息 | 门将站位、扑抢范围一律**不显式标出**——玩家需自行判断 |

> 隐含约束：门将不可见信息保留了"概率判断"的玩法价值；如果未来要做"门将预测"应作为独立高阶道具（默认不开），与现有"瞄准"道具（默认开、画轨迹）解耦。

## 七、与开发 ParametricShot 包的对照与定稿

> 来源：`client_Assets_k1_Script_HotfixScripts_K1D1_Code_Game_Soccer_GamePlay_ParametricShot_README.md`（开发实现文档）。本节对 10 项差异逐项确认定稿，作为主案修订与开发对接的同一信源。

### 7.1 命名映射

| 开发命名 | 设计命名（定稿后） | 说明 |
|---------|-----------------|------|
| Draw | 划线（保留） | 一笔划线决定方向、弧度；力度/挑高系统推 |
| Drag | **弹弓（重做）** | 开发当前两步操作（拖拽+特写选击球点）需改为一步拖拽=反向拉弓 |

### 7.2 10 项差异定稿对照

| # | 差异点 | 我们设计 | 开发现状 | **定稿** | 对开发的要求 |
|---|--------|---------|---------|---------|-------------|
| 1 | 弹弓模式 | 一步拖拽=反向拉弓 | 两步 Drag（拖拽+击球点选点） | **保留弹弓的一步拖拽语义** | 重做 Drag：去掉特写选击球点，改为"按住球反向拉→释放=出脚" |
| 2 | 玩家可控参数 | 划线 2 个 / 弹弓 2 个 | Draw 4 个（方向/弧度/力度/挑高） | **轨迹由 4 参数决定，但玩家手势仅划线/拖拽两种；无法直接对应的参数按规则推出** | 划线：力度/挑高从起点-落点距离推；弹弓：力度=拉弓距离，挑高从力度耦合推 |
| 3 | 击球点 (cx, cy) | 无此概念 | Drag 显式选、Draw 反推 | **完全去除击球点概念** | `Solve` 签名改为 `(direction, power, sideSpinAmount, liftAmount, config) → (velocity, angularVelocity)`；Magnus 系数直接从 sideSpinAmount 给 |
| 4 | 力度-距离关系 | 弹弓非单调（拉满=高调高球） | 单调线性 + 可选 distanceAngleBoost | **改为单调线性 + 远射微抬** | 与开发现状一致，零改动 |
| 5 | 守门切片 | 玩家主动操作（反应时间+方向判断）| 守门员是 NPC，对任何切片预测扑救 | **保留守门切片** | 新增 GoalkeeperSlicePerformer：守门切片下守门员升为玩家可操作角色，反应时间限制，强制划线 |
| 6 | Ready 期相机粗瞄 | 未讨论 | 空白拖动绕球水平环视，按切片配置范围 | **接受、保留粗瞄** | 与开发现状一致；主案补"Ready 期相机粗瞄"段，参数下沉配置表 |
| 7 | 力度基准 | 未明确 | 满力 = 推荐目标距离 × 1.2（动态） | **接受动态力度基准** | 与开发现状一致；系数下沉配置表，可逐切片调 |
| 8 | 模式锁定 | 默认模式 + 随时可改；任意球强制重置 | _aimMode 实例字段，无关内锁定 | **新增切片级配置"默认操作模式"，覆盖玩家外部设置；未配置则沿用上一切片** | 在 `SliceManager.Play` 进入 Ready 时读切片默认模式覆盖 _aimMode；切片配置增加"默认操作模式"字段 |
| 9 | 传球/射门分类 | 切片预设"允许传球" | 事后按球的归宿分类 | **接受事后分类** | 主案去除"允许传球"列；助攻机制重表述为"队友接到再射门进球" |
| 10 | 模式区分手段 | 起手位置区分（划线扇形任意点 vs 弹弓必须从球上） | 都从球上起手，靠 `_aimMode` 字段切 | **两种模式都从足球起手，起手区扩大为"足球周边半径内"；区分靠 UI/设置切换** | 起手区半径下沉配置；扇形约束保持（划线落点/弹弓反向延长线在扇形内） |
