# MindToDoc 策划精简判断梯设计

**日期**：2026-08-06
**状态**：待用户书面复核

## 目标

为 MindToDoc 增加一套轻量、可复用的策划精简判断协议，减少重复规则、错位内容、空章节和无依据派生文档；不得削弱边界情况、数据兼容、设计意图和可评审性。

## 已确认范围

- 借鉴 Ponytail 的“先判断是否需要，再新增最小内容”方法，不安装 Ponytail 插件。
- 新增一个 reference，集中维护判断梯、保护项、审查标签和输出契约。
- `SKILL.md` 只登记路由和调用时机，不复制 reference 细则。
- 不新增自动化脚本；先用真实策划案做行为测试。
- 不修改钉钉测试文档、现有策划产物、模板或其他用户改动。

## RED 基线结论

测试素材为钉钉文档《大地图重构GDD》。三组隔离基线分别施加“当天精简”“半天内能拆都拆”“必须压缩 30%”压力。

当前 Skill 已能稳定保护核心循环、边界情况、数据兼容与设计意图，也能拒绝无图界面标注、无来源音效和 BI 文档。因此本次不重写既有写作纪律。

基线暴露的缺口是审查输出形态不稳定：

- 三组输出使用不同分类和汇总方式，缺少统一审查契约。
- 对流程图、边界表等重复表达的取舍不一致，缺少“一个结论只保留一个详细 SSOT”的固定判定顺序。
- 当前规则散布在文档粒度、主案边界、写作规范和自检清单中，没有面向“精简/压缩/去重/派生物审查”的单一入口。

## 设计

### 1. 策划精简判断梯

处理每条规则、章节、表格或派生文档时，依次判断，命中即停止：

1. 是否属于本期明确范围；不属于则删除或记录为后续范围。
2. 是否已经存在于主案、派生文档、reference、公共配置或既有系统；存在则引用或复用。
3. 是否属于功能规则；技术实现、配置字段、控件表现、排查证据应迁移到对应派生文档。
4. 是否有事实素材支撑；无截图、无音频需求、无 BI 目标时不创建对应派生文档。
5. 是否与其他位置重复；摘要留在关键决策，详细规则只保留一个 SSOT。
6. 是否能合并表达且仍保留触发条件、分支、不满足提示和结果反馈；可以则合并。
7. 前述均不成立时，才新增最小必要内容。

### 2. 保护项

以下内容不参与“为达到字数目标而删除”：

- 设计目的、核心循环和关键决策。
- 触发条件、状态分支、不满足提示和结果反馈。
- 跨系统边界、异常情况、重复请求和活动结束等边界。
- 老客户端、转服、热更、幂等和 KVK 往返等数据兼容。
- 玩家体验与设计意图。
- 用户明确要求保留的内容、版本记录和决策追溯。

若精简后仍未达到目标，报告实际结果与差额，由用户决定是否延期整个非核心范围，不继续删除保护项。

### 3. 审查标签与输出契约

精简审查统一使用以下标签：

| 标签 | 含义 |
|------|------|
| `delete` | 无评审增量的空节、失效内容或纯噪音 |
| `reuse` | 已有系统、规则、公共配置或文档可直接复用 |
| `merge` | 同一结论重复出现，合并到详细 SSOT |
| `relocate` | 内容有效但文档归属错误，迁移到对应派生文档 |
| `clarify` | 伪待定、含糊兜底或缺少拍板人的未决项 |
| `protect` | 命中保护项，必须保留 |

输出顺序固定为：

1. 结论：是否可按目标精简或是否应创建派生文档。
2. 审查表：位置、标签、动作、唯一落点、理由。
3. 保护项：本次明确不删的内容。
4. 汇总：删除、合并、迁移、拒绝创建的数量；不以总字数作为唯一质量指标。

### 4. Skill 路由

在 `SKILL.md` 中只增加三处短路由：

- SSOT 地图登记 `references/spec-minimalism-ladder.md`。
- 阶段 1 在确认模块和交付物范围后，用判断梯做一次“是否需要存在”检查。
- 阶段 3 创建派生文档前逐项检查事实依据；用户提出精简、压缩、去重或过度设计审查时，完整读取该 reference 并按输出契约报告。

同时删除 `SKILL.md` 中绑定 Bash heredoc 的大文档编辑实现说明。它不属于策划方法论，且与跨环境执行无关。

## 验收

修改后用同一钉钉文档复测三组场景：

- 范围审查必须使用统一标签，并为每项给出唯一落点。
- 派生文档压力必须拒绝无素材或无业务目标的空文档。
- 30% 压缩压力必须列出保护项；达不到目标时停止删除并报告差额。
- 三组输出对流程图、重复规则和边界表的判断必须遵循“摘要 + 一个详细 SSOT”。
- `quick_validate.py` 通过，仓库现有测试通过，差异不包含用户已有改动。
