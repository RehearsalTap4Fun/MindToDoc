## 2 改动清单

### 2.1 P0（必须做，阻塞策划侧主案落地）

#### P0-1 弹弓（Drag）重做为一步拖拽

**当前实现**：Ready → 按住球 → Aiming（左右调方向 / 前后调力度）→ 释放 → ContactSelect（特写相机点击球面选击球点）→ Flying。两步操作。

**目标实现**：Ready → 按住球 → 反向拉弓（玩家从球向 A 方向拖动）→ 释放 = 出脚 → Flying。**一步操作，无击球点选点阶段**。

**语义**：
- 玩家从球往 A 方向拖动，球的出脚方向 = 球→A 的反向延长线方向
- 拖动距离映射力度（距离越远力度越大，超过最大值 clamp）
- 释放瞬间：若反向延长线方向落在扇形（含外延）内 = 出脚；落在扇形外 = 取消本次拖拽，玩家可重新起手

**改动点**：
- `DragAimMethod`：去除 `ContactSelect` 阶段，去除对 `BallCloseupCamera` 的依赖
- `ShotAimController`：`UpdateAiming` 释放分支直接调 `Fire`，不再切到特写相机
- 出脚方向计算：`direction = -(dragEnd - ballPos).normalized`（反向延长线在水平面上的投影）
- 出脚扇形判定：与 Draw 共用，方向落在 `AimYawRange` 扇形内才允许出脚
- 力度计算：`power01 = clamp(dragLength / _powerDragPixels, 0, 1)`（保留现有字段）

#### P0-2 击球点 (cx, cy) 完全去除

**当前实现**：`ShotParameters` 含 `contact: Vector2`（单位圆内 (x=水平, y=垂直)），物理求解器据此推侧旋（Magnus）和挑高（仰角 + 后旋）。

**目标实现**：`ShotParameters` 中删除 `contact` 字段；物理求解器直接接收 `sideSpinAmount` 和 `liftAmount` 两个独立参数。

**改动点**：
- `ShotParameters` 字段调整：
  ```
  ShotParameters {
      direction: Vector3 (XZ 单位向量)     // 不变
      power01: float (0~1)                  // 不变
      sideSpinAmount: float (-1~+1)         // 新增，替代 contact.x
      liftAmount: float (0~1)               // 新增，替代 contact.y 的"偏下→挑高"语义
      launch: LaunchMode                    // 不变
      config: ShotConfig                    // 不变
  }
  ```
  - `sideSpinAmount`：负=左弧（球向左拐）、正=右弧、0=无侧旋
  - `liftAmount`：0=贴地平射、1=最大挑高（仰角抬到 `maxLaunchAngle`）
- `ParametricShotModel.Solve` 签名改：从内部"读 contact 推自旋/仰角"改为直接从 `sideSpinAmount` 推 Magnus 角速度、从 `liftAmount` 推仰角偏移
- `ParametricThrowModel.Solve`：手抛本来就忽略 contact，签名同步对齐即可
- `BallCloseupCamera`：保留代码（守门可能复用），但 Drag/Draw 流程不再调用

#### P0-3 守门切片 + GoalkeeperSlicePerformer 新增

**当前实现**：守门员是 NPC，对任何切片完成都做预测扑救（`OnSliceCompleted` 触发），玩家不操作守门。

**目标实现**：新增"守门切片"作为独立 `SliceType`；守门切片下守门员升为玩家可操作角色，反应时间内玩家划线决定扑救方向。

**改动点**：
- `SliceType` 枚举新增 `Goalkeeper`
- 新建 `GoalkeeperSlicePerformer` 实现 `ISlicePerformer`：
  - Ready：相机切到守门视角（守门员第一人称或斜后方）
  - Aiming：启动反应计时器（默认时长由配置决定，~2s 量级）
  - 输入：仅支持划线（`AimMode.Draw`，不可切弹弓）
  - 出脚等价物：玩家划线方向 = 扑救方向（带力度=扑救距离）
  - 完成判定：超时未划 = 失败；划线方向与来球方向夹角 ≤ 阈值 = 扑救成功；否则 = 扑救失败
- `SliceManager`：增加 `_goalkeeperPerformer` 字段（与 `_shotPerformer` 并列），按 `SliceType.Goalkeeper` 派发
- 守门切片专属配置：反应时长、扑救成功角度阈值、扑救距离最大值

**注意**：守门切片下守门员是玩家操作的"切片操作者"，对方射门员是 NPC（自动完成切片）。这与一般切片"玩家操作=进攻方"逻辑相反，需要在 `MatchDriver` 调度逻辑里区分。


### 2.2 P1（重要，但不阻塞核心流程）

#### P1-1 切片级"默认操作模式"覆盖

**当前实现**：`_aimMode` 是 `ShotAimController` 实例字段，由 Inspector / 玩家 UI 设置；进入切片时不重置。

**目标实现**：`SliceConfig` 增加"默认操作模式"字段；`SliceManager.Play` 进入 Ready 时，若切片配置了默认模式则覆盖玩家当前 `_aimMode`，否则沿用玩家上一切片选择。

**改动点**：
- `SliceConfig` 新增字段 `defaultAimMode: AimMode? = null`（可空，null 表示"不强制"）
- `SliceManager.Play` 派发到 `ShotAimController.Perform` 时：
  ```
  if (slice.defaultAimMode != null)
      shotPerformer._aimMode = slice.defaultAimMode;
  // else: 保持上次值
  ```
- 守门切片不走 `_aimMode` 逻辑（独立 Performer）

**策划侧填表预期**：任意球 = `Draw`、点球 = `Drag`、其他 = `null`（沿用）。

#### P1-2 起手区从"球图标点中"扩到"球周边半径内"

**当前实现**：Ready 期按住球进入 Aiming，球的 Collider + RaycastAll 命中即可。

**目标实现**：起手区为以球为中心、半径 `_holdStartRadius` 的圆形区域；玩家在该区域内任意点按下都视为"起手"，按下点的位置不影响后续输入语义（拖拽起点仍取按下点）。

**理由**：玩家不必精准戳球；扩大起手区降低误触取消率。

**改动点**：
- `ShotAimController.UpdateReady`：扩展点中判定逻辑，半径内视为命中
- 新增字段 `_holdStartRadius: float`（默认值待策划填，建议 50~80 像素或对应世界尺度）
- 半径配置可逐切片调（写入 `SliceConfig` 或 `ShotConfig`，由策划决定）

#### P1-3 主案术语对齐："允许传球" → "事后分类"

**当前实现**：开发已是事后分类（射门/传球不预设，看球的归宿决定）。

**目标实现**：与开发一致，无代码改动；策划侧主案文档同步术语。

**改动点**：
- 无代码改动
- 但需要确认：当前事后分类逻辑对所有切片均生效？（点球/任意球场景下，若场上无队友，则不可能产生"传球"结果——这点已天然成立）

## 3 不动的部分（开发现状已与定稿一致，避免误改）

| 项 | 现状 | 定稿确认 |
|----|------|---------|
| Draw 模式（划线） | 一笔划线，反推方向/弧度/力度/挑高 | 保留；详见 §6 验收开放项关于"4 参数生成路径" |
| 力度 → 射程 | 单调线性 `Lerp(minDistance, maxDistance, power01)` | 保留 |
| `distanceAngleBoost` 远射微抬 | 默认关闭、可选开启 | 保留，建议开启起步值 3~5 |
| 力度基准动态计算 | 满力 = 推荐目标距离 × `_powerRangeFactor`（默认 1.2） | 保留 |
| Ready 期相机粗瞄 | 空白处左右拖动绕球水平环视，范围由切片配置 | 保留 |
| 切片冻结 | `SliceManager.Play` 创建切片即冻结其他角色 | 保留 |
| 模式可随时切（无关内锁定）| `_aimMode` 实例字段，不锁 | 保留；P1-1 增加切片默认覆盖即可 |
| 传球/射门事后分类 | 看球的归宿（被接=传、进网=射、停下=死）| 保留 |
| 推荐目标仅作参考 | 不强制玩家朝它踢 | 保留 |
| 确定性回放 | 三参数 + 系数快照 + LaunchMode | 保留；`ShotParameters` 字段调整后回放快照同步更新 |
| 手抛（界外球）模型 | 无旋转、固定高弧、跳过击球点 | 保留；接口签名同步对齐 P0-2 |

## 4 配置表新增字段（策划侧填表 / 开发侧留接入点）

### 4.1 `SliceConfig`（切片级配置，每类切片一行）

| 字段 | 类型 | 含义 | 示例值（策划填表） |
|------|------|------|------------------|
| `defaultAimMode` | `AimMode?` | 进入此切片时强制重置为该模式；null=沿用 | 任意球=Draw、点球=Drag、其他=null |
| `holdStartRadius` | `float` | 起手区半径（像素或世界尺度，与开发约定单位） | 待定，初始 60 |
| `aimYawRange` | `float`（已有） | 扇形张角（度） | 已有 |
| `camYawRange` | `float`（已有） | 粗瞄相机环视范围（度） | 已有 |
| `camYawDefault` | `float`（已有） | 粗瞄默认朝向（相对球→推荐目标的偏角） | 已有 |
| `powerRangeFactor` | `float` | 满力 = 推荐目标距离 × 此值（覆盖默认 1.2） | 一般 1.0~1.5，逐切片调 |

### 4.2 `ShotConfig`（物理系数快照，每次射门随参数存档）

无新增字段；以下为定稿后**意义有所变化**的字段说明：

| 字段 | 现状 | 定稿后语义 |
|------|------|-----------|
| `sidespinFactor` | 与 `contact.x` 一起决定侧旋强度 | 改为与 `sideSpinAmount` 一起决定 |
| `backspinFactor` | 与 `contact.y` 一起决定挑高时的后旋强度 | 改为与 `liftAmount` 一起决定 |
| `verticalAngleRange` | 与 `contact.y` 一起决定仰角偏移上限 | 改为与 `liftAmount` 一起决定 |
| 其他（`maxDistance`、`baseLaunchAngle`、`magnusK`、`distanceAngleBoost` 等） | 不变 | 不变 |

### 4.3 守门切片专属（`GoalkeeperSliceConfig` 或扩展 `SliceConfig`）

| 字段 | 类型 | 含义 |
|------|------|------|
| `reactionTimeSec` | `float` | 反应时长（秒） |
| `saveAngleThresholdDeg` | `float` | 划线方向与来球方向夹角 ≤ 此值视为扑救成功 |
| `maxSaveDistance` | `float` | 扑救距离最大值（划线力度满档对应的扑救范围） |

## 5 验收标准

### 5.1 P0-1 弹弓重做

- [ ] Drag 模式下，按住球开始拖动至释放为单一手势，不进入特写相机
- [ ] 出脚方向与拖拽方向**反向**（拖东南→球飞西北）
- [ ] 拖拽距离归一化为 `power01`，超过 `_powerDragPixels` 后 clamp
- [ ] 释放点对应的"反向延长线方向"在扇形外时，本次拖拽取消，球不出脚
- [ ] 拖拽过程中按住不放可任意重画，结束点跟随手指当前位置
- [ ] 拖拽预览实时按固定间隔刷新轨迹与落点，释放瞬间额外刷新一次

### 5.2 P0-2 击球点去除

- [ ] `ShotParameters.contact` 字段移除（或保留兼容字段但不使用）
- [ ] `ShotParameters` 含 `sideSpinAmount`、`liftAmount` 两个新字段
- [ ] `ParametricShotModel.Solve` 仅依赖新字段计算物理量，不再读 `contact`
- [ ] 已有回放数据的兼容性：旧存档 `contact` 字段需有迁移路径或显式标注"旧版本不可回放"
- [ ] Draw 模式手势→新参数的映射保持原有手感（侧旋强度、挑高高度大体不变）

### 5.3 P0-3 守门切片

- [ ] `SliceType.Goalkeeper` 枚举值新增并被 `SliceManager.Play` 正确识别
- [ ] `GoalkeeperSlicePerformer` 实现 `ISlicePerformer` 接口，可被 `SliceManager` 派发
- [ ] 守门切片下相机切到守门视角，反应计时器启动
- [ ] 玩家划线方向 = 扑救方向，超时 / 角度偏差超阈值 = 扑救失败
- [ ] 守门切片完成后正常进入下一切片或关卡结算
- [ ] 守门切片不响应 `_aimMode` 切换（强制 Draw）
- [ ] 测试场景：`Tools/Football/生成守门测试场景`（与现有 5 类切片测试场景一致的入口）

### 5.4 P1-1 切片默认模式覆盖

- [ ] `SliceConfig.defaultAimMode` 字段存在且可在策划侧 SliceConfig 中配置
- [ ] `SliceManager.Play` 进入 Ready 时，若切片配置了默认模式则覆盖 `_aimMode`
- [ ] 任意球切片配置 `defaultAimMode = Draw` 后，无论玩家上次选什么，进入任意球都自动切到 Draw
- [ ] 玩家在切片内手动切换 `_aimMode` 不影响切片配置；下次进入同切片仍按配置覆盖

### 5.5 P1-2 起手区扩大

- [ ] Ready 期按下点不必精准命中球图标，半径 `_holdStartRadius` 内任意点视为起手
- [ ] 起手点位置不影响后续输入语义（拖拽起点取按下点）
- [ ] `_holdStartRadius` 可逐切片配置

## 6 待研发反馈的开放项

下列点需要研发评估可行性 / 工作量后回话：

### 6.1 P0-2 旧回放数据兼容

`ShotParameters.contact` 字段移除后，已有的回放存档（如果有）能否迁移？
- 若可迁移：从旧 `contact.x` 推 `sideSpinAmount`、从 `contact.y` 推 `liftAmount` 的反向公式
- 若不可迁移：旧存档统一标注"不可回放"，新存档使用新格式

### 6.2 P0-3 守门切片调度

守门切片下"玩家操作守门员、对方射门员是 NPC"的调度逻辑：
- `MatchDriver._holder` 是否需要扩展为"当前操作角色"而非"持球者"？
- 守门切片完成后控球权回到对方还是按规则交回？
- 现有"球员模型隐藏"逻辑（防遮挡脚下球）在守门切片下是否需要调整？

### 6.3 P1-2 起手区半径单位

`_holdStartRadius` 是像素（屏幕空间）还是世界尺度（米）？
- 像素更直观，不同分辨率下需要做 dpi 校准
- 世界尺度与扇形/距离一致，但远近镜头下视觉大小不一
- 建议研发选一种并固定

### 6.4 守门切片输入：划线 vs 单点点击

主案描述守门切片用划线（方向 + 力度），但参考真实点球扑救，玩家可能更习惯"在球门画面上点一下扑救方向"。
- 划线（保持当前定稿）：方向 + 力度 = 扑救距离
- 单点：仅方向，扑救距离系统给定
- 哪种更易实现 + 手感更好，请研发评估反馈

### 6.5 距离量纲与 dpi

划线模式中"路径 Δ → 水平转弯量"的映射定为"按设备 dpi 换算物理距离"。
- 现有代码 `_drawFullBowPixels=140` 是像素阈值，未做 dpi 换算
- 不同分辨率手机上手感是否需要做归一？
- 若需要：由开发侧统一处理，还是策划侧分档配？
