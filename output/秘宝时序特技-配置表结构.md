# 秘宝时序特技 · 配置表结构（数值策划填表）

> **定位**：仅描述数值/关卡/活动策划在 Excel 中**需要填写**的配置表字段。  
> **规则依据**：主策划案 `秘宝时序特技.md`。  
> **结构依据**：既有结构已核对 `dataconfig` 的 `Treasure.xlsx`（`TreasureItemCfg` / `AttributeCfg` / `StuntCfg`）、`Item.xlsx`、`Itemaccess.xlsx`、`ActivityKingdomWars.xlsx`、`VersionRewardSource.xlsx`、`Config.xlsx`、`ConstConfig.xlsx`；本案新增字段与新增页签尚未落表，标注为**设计结构**。

---

## 文档边界

### 本文档包含

- 新秘宝与秘宝碎片的物品、获取途径、商店货架与价格。
- 时序特技的节点、方向、效果原语与分等级参数。
- 特技等级的合成消耗曲线、碎片合成所需数量。
- 真实交战掉落的概率、保底与每日上限，参与型金币的积分阶梯。
- 战斗结算相关的可调常量（真实交战比例、连战窗口、减伤合计上限等）。

### 本文档不包含（由程序/服务端定义）

| 类型 | 示例 | 说明 |
|------|------|------|
| 玩家存档 | 秘宝实例的特技等级、累计合并件数、碎片余额 | 运行时持久化，不进策划表 |
| 局内/运行时 | 回合计数、承伤/输出累计、免疫状态、节点已触发标记、连战窗口剩余时间 | 战斗与部队内存态 |
| 接口/协议/DB | — | 不纳入配置结构及本项目派生交付 |

- 节点判定顺序、单次伤害结算顺序、部队内"每节点一条"的取舍**算法**写在主策划案。
- 本文只列可调系数所在配置表。

## 秘宝本体

### TreasureItemCfg（改）

- 既有字段沿用：`CfgID` / `Part` / `Quality` / `ExAtt` / `ExStunt` / `Power` / `Access` / `IfShow` / `Name` / `Icon` / `ItemId`。
- 本案新增与改动：

| 字段 | 类型 | 说明 | 填表要点 |
|------|------|------|----------|
| `Node` | int | 时序节点：1 开战 / 2 战中 / 3 追击 / 4 战后 | 必须与 `Part` 对应（指环=1、项链=2、号角=3、护符=4），存量行留空 |
| `Direction` | int | 方向：1 进攻 / 2 守御 / 3 续战 | 每个 `Part` 下三个方向各一件；存量行留空 |
| `ExStunt` | int数组 | 挂载的时序特技 ID | 新秘宝各挂一条，取自 `StuntCfg`；不与存量的计数特技混挂 |
| `ExAtt` | int数组 | 属性词条 ID | 沿用 `91010` 英雄战力百分比，同品质取值与存量一致 |
| `IfShow` | int | 是否在图鉴与商店可见 | 12 件新秘宝填 1；原 12 个占位坑位行按替换或废弃处理，见待确认项 |
| `Access` | int数组 | 获取途径枚举 | 指向 `ItemaccessCfg` 的新秘宝途径值 |

### AttributeCfg（沿用）

- 不新增字段。
- 新秘宝复用 `91010`（英雄战力增加百分比），同品质取值与存量橙色一致。
- `AttributeCfg` 中已定义但本案不使用的词条保持原样，不清理。

### StuntCfg（改）

- 既有字段沿用：`CfgID` / `SkillID` / `ShowDesc` / `Name` / `Quality` / `Count` / `Group` / `Lv` / `Parameter` / `ShowInfo`。
- 本案新增：

| 字段 | 类型 | 说明 | 填表要点 |
|------|------|------|----------|
| `Node` | int | 触发节点：1 开战 / 2 战中 / 3 追击 / 4 战后 | 与所挂秘宝的 `Node` 必须一致 |
| `Direction` | int | 方向：1 进攻 / 2 守御 / 3 续战 | 同节点内三条方向互不重复 |
| `Primitive` | int | 效果原语：1 限时输出加成 / 2 限时减伤 / 3 限时伤兵回战率 / 4 阈值一次性伤害 / 5 限时免疫 / 6 一次性伤兵回战 / 7 至战斗结束的敌方伤害降低 / 8 战后就地恢复 / 9 下一场授予效果 | 同原语的新特技只需配表；新原语需程序支持，不可自行新增枚举 |
| `TriggerRatio` | float | 阈值型特技的触发兵力比例 | 仅 `Node=2/3` 填写；战中三条由高到低（护身 > 重整 > 雷霆），追击三条可相同 |
| `LvMax` | int | 特技等级上限 | 与 `TreasureStuntLvCfg` 的最大 `Lv` 一致 |
| `Group` | int | 互斥组 | 新特技按「同一特技种类」一组，同组只生效等级最高的一条 |
| `Count` | int | 计数器 | 新特技一律填 0（不使用计数制）；存量的 9104/9106 保持原值 |
| `ShowDesc` / `ShowInfo` | string | 多语言 key | 按 `Treasure_` 前缀命名并查重；战报展示文案单列 |

### TreasureStuntLvCfg（新）

每条特技每个等级一行。参数列含义随 `StuntCfg.Primitive` 变化，在 `ParamDesc` 里写清。

| 字段 | 类型 | 说明 | 填表要点 |
|------|------|------|----------|
| `CfgID` | int | 主键 | 建议 `特技ID * 100 + Lv` |
| `StuntID` | int | 所属特技 | 指向 `StuntCfg.CfgID` |
| `Lv` | int | 特技等级 | 从 1 连续递增至 `LvMax` |
| `Param1` | float | 主参数：伤害加成 / 减伤幅度 / 回战率 / 伤害比例 / 恢复比例 | 百分比按小数或百分点填，全表统一口径 |
| `Param2` | float | 次参数：持续回合数 / 免疫回合数 / 回城加速幅度 | 无次参数的特技留空 |
| `MergeNeed` | int | 升到本等级所需的**累计**同名件数 | Lv1 填 0；后续递增，不是每级增量 |
| `ParamDesc` | string | 本行两个参数的业务含义 | 给程序与数值对齐口径用，不下发客户端 |

### TreasureShardCfg（新）

| 字段 | 类型 | 说明 | 填表要点 |
|------|------|------|----------|
| `CfgID` | int | 主键 | — |
| `ShardItemID` | int | 碎片道具 ID | 指向 `Item.xlsx` 新增的碎片道具 |
| `NeedCount` | int | 合成一件整件所需碎片数 | 与商店整件价格保持相对关系 |
| `TargetRange` | int数组 | 可合成的目标秘宝范围 | 填已解锁的新秘宝 `TreasureItemCfg.CfgID`；留空表示全部已解锁 |
| `ResultLv` | int | 合成结果的特技等级 | 固定填 1 |

### TreasureDropCfg（新）

| 字段 | 类型 | 说明 | 填表要点 |
|------|------|------|----------|
| `CfgID` | int | 主键 | — |
| `BattleType` | int数组 | 适用战斗类型 | 按现有野战/攻城/集结/守城判定填；对 NPC 不填 |
| `DropRate` | float | 单场真实交战胜利的碎片产出概率 | — |
| `DropCount` | int数组 | 单次产出碎片数量区间 | 下限=上限即固定值 |
| `GuaranteeBattles` | int | 连续未产出的保底场次 | 达到后下一次真实交战胜利必定产出 |
| `DailyCap` | int | 每服务器日的碎片产出上限 | 达到后不再产出，战报不再提示 |

| 字段 | 类型 | 说明 | 填表要点 |
|------|------|------|----------|
| `CfgID` | int | 主键 | — |
| `ContentID` | int | KVK 玩法内容 ID | 与现有 KVK 排行奖励同口径（如 `8502`） |
| `Tier` | int | 阶梯档位序号 | 从 1 递增 |

### ActvKingdomWarsShopCfg（改）

| 字段 | 类型 | 说明 | 填表要点 |
|------|------|------|----------|
| `unlock_time` | int | 货架解锁时点（KVK 任务开始后的秒数） | 从现行 `1209600`（14 天）提前至整备阶段结束对应值 |
| `limit` | int | 每期每件限购次数 | 从 `1` 改为按赛季可购买多件的上限 |
| `ShardShelf` | int | 是否为碎片货架 | 新增碎片货架行填 1，货币为破碎大陆金币 |

### KvKAchievementCfg（改）

- 不新增字段，只扩容数据行。
- 原仅 1 条成就发放征服金币，本案扩为多条：首次参战、累计击杀、累计守城、集结参与等方向。
- 每条每赛季每人限一次，奖励组指向 `VersionRewardBaseCfg`。

### 战斗与投放常量（`ConstConfigCfg` 新增）

| 语义 | 说明 | 填表要点 |
|------|------|----------|
| 真实交战兵力比例 | 战后节点与碎片掉落的判定门槛：敌方开战兵力 ÷ 我方开战兵力的下限 | 由数值拍板；同一常量供战后节点与掉落共用 |
| 连战窗口时长 | 乘胜/坚守授予效果的有效期 | 秒 |
| 接战冷却时长 | 同一部队与同一敌方单位再次进入战斗时，开战节点不触发的时长 | 秒，示例 60 秒；冷却记录随部队保留至到期 |
| 减伤合计上限 | 战阵、坚守、压制与其他系统同类减伤相加后的封顶 | 与现有减伤体系口径对齐 |
| 碎片持有上限 | 碎片道具的持有上限 | 也可直接用 `Item.MaxOwn`，二选一，避免双轨 |
| 赛季金币个人上限 | 单赛季单玩家可获得的征服金币上限，跨来源累计 | 与阶梯、成就、礼物三路共用 |

- 以上常量只写语义与用途。
- **常量 ID 由配置负责人分配后回填**，不在本文档预设 ID。

## 待确认项

- `ItemaccessCfg` 的枚举值 `14`（现行秘宝获取途径）在表内注释里未定义，新秘宝与碎片沿用该值还是新增枚举，需要与配置负责人确认后再填 `Access`。
- `TreasureItemCfg` 中原有 12 个 `IfShow=0` 的橙色占位坑位（各部位序号 01–03）：本案 12 件新秘宝是**改写这些行**还是新增行并把占位行标废弃，影响 ID 号段与客户端图鉴顺序。
- 特技等级是否计入秘宝战力（`RallyShowCfg` type `39`）尚未拍板。
  - 若计入，需要在 `TreasureStuntLvCfg` 增加一列战力系数，并同步 `PowerStrong` 的推荐战力区间。
- `ActvKingdomWarsRwdCfg.AllianceRewardIdNum`（第 1 名 5、第 2 名 3、第 3 名 2、第 4–8 名 1）在服务端无读取点，联盟礼物实际每盟只发一份。
  - 改为按人数自动发放前，需确认是让该字段生效还是改用新字段，再决定本表是否新增列。
- 赛季上限的判定口径为「赛季 × 玩家」跨来源累计，需确认由服务端统一记账还是各来源各自限流。
  - 前者不需要在各来源表重复配上限列。
- 碎片合成整件是否允许合成尚未在商店或图鉴中出现过的秘宝，决定 `TreasureShardCfg.TargetRange` 是否必填。
