# 交互预演网页

把已确认的主案规则做成可点击的流程网页，用于两件事：

- **讲解**：其他职能照着场景点一遍，看到每一步命中主案哪条规则。
- **查漏**：把规则串成可操作流程时，主案没写结果的交互会暴露出来。

类型定位和触发条件以 `derived-documents-workflow.md` 为准，本文件只写怎么做。

## 定位与边界

- 预演是主案的**演示**，不是规则来源。规则、文案、数值只在主案和对应派生定义。
- 预演不替代界面标注。它表达“点什么、到哪里、出什么结果”，不定义新控件的布局、尺寸和美术表现。
- 涉及的界面在项目里已经存在时，直接采用现有界面的布局和交互方式，见「还原现有界面」。只有新界面和查不到来源的界面才用灰盒或示意框。
- 预演不替代宣讲网页。宣讲讲设计目的和方案全貌，预演讲流程怎么走。两者可同时存在。
- 预演不写入主案正文。主案只在 `# 派生文档说明` 链接它。

## 开始前的门槛

- 本次要预演的模块，规则已经过用户确认。
- 主案已有版本号，预演记录所依据的版本。
- 规则还在讨论的模块不进预演。需要用预演辅助讨论时，在待定细节里列出，不自行补规则。

## 制作步骤

1. **抽规则**：从主案详细规则逐条列出要演示的规则。
   - 每条登记 `id`、所在章节标题 `section`、一句话 `summary`。
   - 一条规则只对应一个可判定的结果。含多个分支的规则拆成多条。
   - 纯表现要求（字号、颜色、底图）不登记。
2. **列界面与弹窗**：只列流程经过的界面，逐个判定来源。
   - 常用界面库里已有的界面：直接用，不需要 Unity。见「常用界面库」。
   - 库里没有的现有界面：从客户端找到对应 prefab 和界面脚本，按「还原现有界面」导出。
   - 新界面：用项目通用样式的现有组件拼（通用弹窗、通用按钮等能复用的直接导出），其余用示意框。
   - 有已确认效果图时，元素命名和文案与效果图一致。
3. **列前置条件**：把决定分支走向的条件做成可调参数。
   - 主案给出的值标 `origin: 主案`，例如阈值的初始配置。
   - 主案没给、只为演示而设的值标 `origin: 示意`，页面会显示“示意值”。
   - 主案写“由配置表定义”的数值一律是示意值，不在预演里定数。
4. **排场景**：每个场景是一条从起点到结果的完整路径。
   - 主流程至少一个。
   - 每个不满足分支、取消或关闭、恢复、异常与边界各至少一个。
   - 每条登记的规则至少被一个场景命中。
   - 场景名用玩家看得懂的说法，写“刚好等于阈值，不弹窗”，不写“边界值用例”。
5. **写流程**：在模板的 `preview-flow` 里定义界面、弹窗和操作。
   - 操作里用 `c.hit('R3')` 声明命中的规则，可附一句带实际数值的说明。
   - 判断条件必须能在主案里找到对应句子。
6. **记待定细节**：见下一节。
7. **校验与走查**：见「校验」。

## 待定细节

做流程时遇到主案没有定义结果的交互，按以下方式处理：

- 不替主案做决定，不按经验补一个“合理”结果。
- 在 `gaps` 登记：`id`、问题 `question`、出现位置 `where`、待谁拍板 `owner`，`status` 写 `open`。
- 流程走到该处时用 `c.gap('G1')` 标出，页面在规则追踪和“待定细节”页显示。
- 交付预演时把待定细节逐条列给用户。
- 用户拍板后的顺序固定：
  1. 结论写回主案，补变更记录。
  2. 按新规则更新预演的规则、场景和流程，版本号同步。
  3. 从 `gaps` 删除该条。

“现有规则”“沿用通用流程”这类主案已明确交给既有系统的部分不算待定细节。预演里用〔现有规则反馈：……〕标出，不编造具体文案。

## 事实约束

- 不新增规则，不改规则，不合并主案里分开判断的条件。
- 界面文案取主案或界面标注原文。主案没给文案的提示用〔〕标明来源。
- 不出现主案没有的入口、按钮和奖励。
- 示意值只用于触发分支，不暗示推荐配置。
- 页面顶部保留来源声明：全灰盒时写“灰盒示意”，用了现有界面时写明界面取自客户端、虚线框为示意。
- 现有界面上本次需求没有改动的部分保持原样，不借预演调整。

## 还原现有界面

做法是让 Unity 把现有界面按真实状态渲染成图层，网页只负责叠放图层、放点击热区、覆盖会变化的文字。字体、描边、九宫格与游戏内一致，不需要在网页里重做排版。

**前提**

- 客户端工程在本机，Unity 编辑器已打开该工程且没有在运行游戏。
- 会话里可以调用 UnityMCP 的 `execute_code`。
- 不满足时退回灰盒，并在交付说明里写明哪些界面没有还原及原因。

**步骤**

1. **定位界面**：从功能相关的多语言 key 或类名找到界面脚本，再从脚本的 `[Popup("...")]` 找到 prefab。
   - 例：`UIRallyList` 对应 `Mass/New/UIMassList_Build`。
   - 交互方式以界面脚本为准：点击后做什么、弹窗用哪组按钮、文字取哪个 key。
2. **普查节点**：写一份只含 `prefab` 和 `"survey": true` 的规格，导出后查看节点路径、文字和按钮。
3. **写导出规格**：每个图层说明要哪个子树、哪些节点显示或隐藏、哪些文字改写、哪些文字留给网页动态显示。
4. **导出**：把 `scripts/unity/export_ui_layers.cs` 里的 `__SPEC_PATH__` 换成规格文件的绝对路径，整段交给 `execute_code` 执行。
5. **看图核对**：逐张查看导出的图片，确认状态正确、没有多余的模板节点。
6. **写入网页**：`python scripts/build_preview_ui.py <来源>... <预演.html>`。
   - 来源可以写多个：图层目录取全部图层，单个 `<名称>.json` 只取这一个。
   - 不同来源出现同名图层时报错，不会悄悄覆盖。
7. **写流程**：在 `preview-flow` 里用 `c.layer(...)` 摆放图层并绑定操作。

规格和导出的图层放在 `output/ui-preview/<功能名>/`，随预演一起保留，主案变更后可重新导出。

**导出规格字段**

| 字段 | 说明 |
|---|---|
| `out` | 输出目录，相对路径以规格文件所在目录为准 |
| `scale` | 渲染缩放，默认 `0.5`。设计分辨率默认 1080×1920，可用 `design` 改 |
| `layers[].name` | 图层名，网页里用它引用 |
| `layers[].prefab` | prefab 的工程内路径 |
| `layers[].root` | 只渲染这个子树。不写则整屏 |
| `layers[].show`、`hide` | 强制显示或隐藏的节点路径 |
| `layers[].text` | 改写固定文字：`{节点路径: 文字}` |
| `layers[].slots` | 运行时才确定的文字：`{槽名: 节点路径}`。导出时隐去，网页按原位置、字号、颜色覆盖。定宽换行的正文会在原矩形内换行 |
| `layers[].slots` 的对象写法 | `{槽名: {node, blank, outline}}`。`blank` 是同一按钮上其余要隐去的文字节点，`outline` 指定描边色 |
| `layers[].invisible` | 不画出来但保留排版占位的节点，例如奖励格、列表条目模板。网页在该区域另行摆放内容 |
| `layers[].title`、`note` | 给人看的界面名和使用说明，原样带进图层信息和清单 |
| `layers[].hotspots` | 可点击区域：`{热区名: 节点路径}` |
| `layers[].place` | 把子树移到指定左上角位置，用于从屏幕外滑入的面板 |
| `layers[].pad` | 子树图层四周留白，容纳阴影和外发光 |
| `layers[].transparent` | 默认 `true`，导出带透明度的图层。整屏底图写 `false` |
| `layers[].survey` | 输出全部节点清单，用于找路径 |

**网页里使用图层**

- `c.layer(名称, {x, y, slots, acts})`：摆放一个图层。
  - `x`、`y` 不写时用导出时的原位置。
  - `slots` 的值是字符串，或 `[[文字, 颜色], ...]`。
  - `acts` 把热区绑定到操作：`{热区名: {act, arg, label}}`。`label` 写按钮上的字，用于规则追踪。
- `c.backdrop(说明)`：没有对应 prefab 的背景，例如大地图。
- `c.note(x, y, 宽, 文字, 标签, 操作)`：虚线示意框。用于新增内容、演示数值和演示辅助入口，和现有界面区分开。
- 坐标一律用设计分辨率，引擎整体缩放到手机框内。

**约束**

- 导出在 Unity 的预览场景里进行，只改临时实例。不保存场景，不修改 prefab 和任何工程文件。
- 界面运行时由代码填充的内容，按界面脚本的真实分支设置，不凭印象摆。拿不准的状态先读脚本。
- 现有界面里不存在的入口不画进图层。演示需要但游戏里没有的操作（例如“模拟系统触发”）用虚线示意框，并标“演示辅助”。
- 图层内嵌后网页仍是单文件。包含项目美术资源，只在内部传阅。
- 界面脚本里读到的实现事实如果主案没写，按「待定细节」处理：列给用户，由用户决定是否补进主案。

## 常用界面库

`ui-library/<项目>/` 是多个功能共用的常用界面。获取到本机后，做预演时直接取用，不需要再打开 Unity。

**先获取，再做预演**

- 图层是项目美术资源，只放本机，不进仓库。仓库里只有导出规格 `spec.json`。
- 每次做涉及已有界面的预演前，先执行 `python scripts/ui_library.py status ui-library/<项目>`。
- 提示未获取、缺图层或规格已变时，按以下顺序获取：
  1. `python scripts/ui_library.py prepare ui-library/<项目>`，生成导出代码。
  2. 读取生成的文件，全文交给 UnityMCP 的 `execute_code` 执行。前提同「还原现有界面」。
  3. 返回内容提示找不到 prefab 或节点时，客户端界面已改动：修正 `spec.json` 后重新执行。
  4. `python scripts/ui_library.py finish ui-library/<项目> --client <客户端仓库路径>`，核对并记录来源。
  5. 逐张看图确认状态正确。
- 本机没有客户端工程或 Unity 时无法获取：这些界面用灰盒，并在交付说明里写明原因。
- 不从其他设备拷贝图层来绕过获取，除非用户明确这样安排。

**库的内容与用法**

- K1 的库在 `ui-library/k1/`，收录范围见该目录的 `README.md`，获取后带缩略图的清单在 `layers/README.md`。
  - 通用弹窗：确认弹窗三种按钮组合、文字弹窗、长文弹窗、消耗确认、恭喜获得、奖励列表、道具使用、道具购买。
  - 面板与入口：出征面板、主界面底部导航。
  - 整屏界面：任务、排行榜、邮件、聊天、联盟、领主信息、英雄列表。
- **取用**：把图层文件作为来源写进网页，例如 `ui-library/k1/layers/msgbox_two.json`。
- **弹窗文字**：标题、正文、按钮字都是文字槽，在流程里按主案文案填写。字体是系统字体，和游戏内略有差别。
- **整屏界面**：内容是 prefab 自带的占位数据，只表达布局和入口位置。需要真实状态时按「还原现有界面」为该功能单独导出。
- **按钮组合**：通用确认弹窗用哪组按钮，以界面脚本里的取值为准，不凭印象选。
- **查看清单**：`python scripts/list_ui_layers.py ui-library/k1/layers`。
- **维护**：客户端界面改版后重新获取。`layers/.export.json` 记有导出日期、客户端分支和提交。
- **新增**：多个功能都用到的界面才进库。只有一个功能用到的图层放在 `output/ui-preview/<功能名>/`，其中的 `layers/` 同样只放本机，按该目录的 `spec.json` 重新导出。

## 页面与模板

- 模板：`templates/interactive-preview.html`，自带示例可直接运行。
- 产物：`output/<功能名>-交互预演.html`，单文件，离线可打开。
- 只改两个脚本块：
  - `preview-data`：`meta`、`rules`、`params`、`scenarios`、`gaps`。
  - `preview-flow`：`initial`、`state`、`screens`、`modals`、`actions`。
- 引擎块 `preview-engine` 保持与模板一致，校验脚本会比对。
- 可点击元素写 `data-act="操作名"`，需要参数时加 `data-arg`。
- 灰盒组件用模板自带的 `gb-*` 样式，不引入外部字体、脚本和图片链接。
- 现有界面图层由脚本内嵌进网页，不手改 `preview-ui` 块。

数据字段：

| 块 | 字段 | 说明 |
|---|---|---|
| `meta` | `feature`、`source`、`source_version` | 功能名、主案相对路径、所依据的主案版本 |
| `rules[]` | `id`、`section`、`summary` | `section` 写主案标题原文，多级用 `A > B` |
| `params[]` | `id`、`label`、`type`、`value`、`origin` | `type` 为 `toggle`、`number`、`select`；数值型另写 `min`、`max`、`step`、`unit` |
| `scenarios[]` | `id`、`kind`、`name`、`params`、`steps`、`expect` | `steps` 每步含 `act` 与给人看的 `label` |
| `scenarios[].expect` | `screen`、`modal`、`hits`、`gaps`、`result` | 回放结束时所在界面、弹窗、命中的规则与待定细节、一句话结果 |
| `gaps[]` | `id`、`question`、`where`、`owner`、`status` | 只保留未拍板项 |

## 校验

```bash
python scripts/check_preview.py output/<功能名>-交互预演.html
python scripts/check_preview.py --allow-open-gaps output/<功能名>-交互预演.html   # 评审中，保留待定细节
python scripts/check_preview.py --open output/<功能名>-交互预演.html              # 通过后用默认浏览器打开
```

- 生成或更新预演后，默认带 `--open` 执行，检查通过即在用户的默认浏览器打开，不需要用户另行要求。
- 存在待定细节时同时加 `--allow-open-gaps`，打开后把待定细节逐条列给用户。
- 检查未通过时不打开，先修正。
- 无法调起浏览器的环境（远程、无桌面）给出文件的绝对路径。

脚本核对以下内容，不改写文件：

- 不加载外部资源，本地资源存在。
- 引擎与模板一致。
- 界面图层已内嵌，并记录了来源 prefab。
- 每条规则引用的章节标题在主案中存在。
- 预演依据的版本是主案变更记录里的最新版本。
- 每条规则至少被一个场景覆盖。
- 用 Node 逐场景回放（`scripts/preview_runner.cjs`），结束界面、弹窗和命中规则与 `expect` 一致。
- 存在未拍板的待定细节时默认不通过。

脚本通过后仍须人工走查：

- 在浏览器里逐场景点完，再不按场景自由操作一遍。
- 对照主案逐条核对规则摘要没有改变原意。
- 确认每个示意值都标了“示意值”。
- 用了现有界面时，对照游戏内截图确认图层状态与真实界面一致。

没有 Node 时脚本报错并说明。加 `--static` 只做静态检查，此时不能说场景已验证。

## 变更联动

- 主案规则变化后，预演的版本检查会失败。
- 先重审受影响的规则、场景和流程，再更新 `source_version`。客户端界面有改动时重新导出图层。只改版本号不重审，等于让检查失效。
- 来不及更新时，在交付登记里把预演标为 `pending`，不作为当前版本对外演示。
- 登记类型用 `preview`，方法见 `delivery-quality.md`。
