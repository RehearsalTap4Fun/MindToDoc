# MindToDoc 设计文档

**日期**: 2026-06-01  
**状态**: ~~已批准设计，待写实现计划~~ → **已归档（superseded by SKILL.md v2 / system-design-doc）**

## 目标

把粗糙的移动游戏想法（脑图、框架性文档、参考游戏名）转化为一份**高度专业、可直接用于开发**的 md 文档。中间需要确认方案细节、补充流程图与交互原型。

## 形态

一个 Superpowers 风格的 Skill（`mindtodoc`）。技能负责流程与交互；文档结构来自独立的模板文件，是"专业结构"的唯一真相来源，方便按团队规范修改。

## 目录结构

```
MindToDoc/
├── SKILL.md                      # 技能主文件（流程、提问逻辑、降级规则）
├── templates/
│   ├── doc-structure.md          # 主文档骨架
│   └── system-module.md          # 单个系统模块小节模板
├── input/                        # 用户放脑图、框架文档、参考游戏名
│   └── .gitkeep
└── output/
    ├── <游戏名>-开发文档.md       # 生成的主文档
    └── prototypes/               # ui-ux-pro-max 生成的 HTML 原型
```

## 文档结构

```
# <游戏名> 开发文档
## 1. 概述          (定位 / 核心玩法 / 参考游戏对标 / 目标平台)
## 2. 核心玩法机制    (玩法循环 / 全局规则 / 数值框架)
## 3. 系统设计       (每个系统一份 system-module)
## 4. Checklist     (开发交付检查清单)
```

每个系统模块为自包含单元，小节顺序固定：

```
### 3.x <系统名>
#### 规则与逻辑
#### 流程图          (Mermaid 代码块)
#### 界面原型        (链接 output/prototypes/<系统>.html + 要点说明)
#### 数据结构 / 配置表 (表格：字段 | 类型 | 说明 | 取值范围)
```

设计意图：程序员翻到某个系统，规则、流程、界面、数据表一站式齐全，可独立开发。

## 工作流程（逐系统深入）

- **阶段 0 · 读取输入**：扫描 `input/`，消化所有素材。
- **阶段 1 · 确认整体框架**：汇报理解到的定位、核心玩法、目标平台、系统模块清单及优先级，用户确认或调整。产出文档第 1、2 章。
- **阶段 2 · 逐系统深入**：对每个系统循环 —— 确认规则细节（追问空白点）→ 生成流程图 → 生成界面原型 → 生成数据结构/配置表 → 用户确认 → 下一个。每走完一个系统，其完整模块追加进主文档。
- **阶段 3 · 收尾**：生成 Checklist 章节，输出完整主文档。

## 外部技能集成（软依赖 + 降级）

- **流程图**：优先用社区 mermaid 技能；未装则直接手写 Mermaid 代码块。
- **界面原型**：优先调用 `ui-ux-pro-max`；未装则手写 HTML/线框示意。

核心流程不被第三方技能绑死，永远能跑。

## 边界处理

- `input/` 为空 → 提示用户先放素材，不硬跑。
- 输入残缺/矛盾 → 阶段 1 列出"待确认假设"，由用户拍板，不擅自编造。
- 参考游戏只有名字 → 基于公开认知补充对标要点，标注"需用户确认"。
- 外部技能未装 → 按降级规则走，并在该处留一行提示。

## 验证方式

用一个最小真实样例跑通：在 `input/` 放一份简短示例（如"一个 roguelike 卡牌手游"几句话 + 1 个参考游戏名），完整跑一遍流程，确认产出一份结构正确、含至少 1 个完整系统模块（规则+流程图+原型+数据表）的 md。
