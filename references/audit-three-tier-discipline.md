# 审核三档断言纪律

> 配置/坐标/数值审核类任务,初判通过后必须主动列「硬范围 / 软分布 / 设计意图」三档断言,逐档判定;只有三档都通过才能报"合规"。
>
> 适用场景:任何「请审核 X 是否合规」「按新参数调整 Y」「检查 Z 是否符合协议」的请求。
> 用法:接到审核类任务时,先在脑内或回答里走一遍三档,再决定动手位置。

---

## 背景

本项目里发生过的真实摩擦(2026-06-24 坐标系协议数值变更下游同步):

- 协议 z 半场 120→60 数值变更后,我让范围 lint(`check_preset_consistency.py` 验 [-60,0])一次过,报"50 preset 全部合规"。
- 用户追问"是否越敌方半场 [-30, 0]" → 扫出 16 处越界 → 我做 5 处 ball_z clamp 让"硬范围"过。
- 用户再追问"为什么不按 0.5 缩放" → 我承认偷懒,提出按比例缩。
- 用户第三次追问"按设计意图检验,不盲目缩放" → 我才回到"门-球真实距离"语义重写 26 个 preset(单刀 23m→13m、远射 29m→12m、吊射 28m→18m)。

代价:三轮往返,前两轮的改动作废大半;若用户没耐心追第三轮,主线就会留下设计语义已漂移的 26 个 preset,被后续 instance / 数值平衡环节继承,极难定位。

根因:我默认走最便宜路径——「跑 lint,过则收工」。范围 lint 是最弱的护栏,设计意图不能用 lint 替代。

---

## 三档断言(审核类任务必走)

接到审核类任务后,**在动手前**先列出对应三档,逐档明示判定结果:

### 第一档:硬范围(hard bounds)

可由 lint / assert 自动校验的最弱约束。

- 坐标在合法盒子内、ID 不重、JSON 解析过、字段类型对。
- 通过:不代表合规,只代表"不会立即崩"。
- **不能单独作为"合规"结论**。

### 第二档:软分布(soft distribution)

数据应大致落在的统计区间,常以"主要发生在..."「典型值..."「常见范围..."表述。

- 协议里所有"应该"「主要"「常见"「通常"的语句都属于此档。
- 通过:数据不光合法,还落在协议的常见范围内。
- 越界需明示数量与最大偏离,而非压成 0/1 布尔。

### 第三档:设计意图(design intent)

数据**代表什么**,与玩家体验/物理直觉/真实参照的一致性。

- 坐标审核:门-球真实距离、球员-球距离、玩家可视距离。
- 数值平衡:难度梯度、奖励曲率、概率分布形状。
- 关卡:节奏感、卡点位置、引导明确性。
- 通过:每条数据回到"它代表的玩法/物理/体验"语境下仍然成立。
- **是最强约束,也是 LLM 最容易跳过的一档**——因为它无法 lint,必须逐条人读 + 比对设计文档。

## 触发清单

凡用户消息含以下关键词,默认走三档:

- "审核 / 检查 / 检验 / 验证 / 复核 / 复审"
- "是否合规 / 是否符合 / 是否满足"
- "按新参数 / 按新协议 / 按新标准 调整 / 同步 / 更新"
- "重新 / 重做 / 重写 / 重排"配置/数据

不必走三档(直接答):

- "运行某脚本"「跑测试」「重生成 xlsx" 等纯执行任务。
- 用户已明示"只看 X 档"(如 "只要 lint 过就行" / "只看硬范围")。

---

## 报告模板

审核类任务回答结尾必含三档结论,例如:

```
**三档结论:**
- 硬范围:50/50 通过(z ∈ [-60, 0])
- 软分布:34/50 通过,16 处越敌方半场最大偏离 13m(preset 16/19/20/21/22/23/26/28/48/49 等)
- 设计意图:**不通过**,旧场地缩半后所有 attack 类 preset 的门-球距离从 23-36m → 在新场地等效 12-18m 才合理;当前数据保留旧 m 值,实际语义已从"禁区外远射"漂到"中场长射"。

建议先决策第三档,再决定动什么。
```
