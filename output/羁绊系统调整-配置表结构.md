# 配置表概览

## 配置文件清单

| 文件 | 页签数 | 用途 | 策划维护 |
|------|--------|------|----------|
| `HeroBondsSkill.xlsx` | 3 | 维护六类羁绊机制的等级效果、解锁升级条件、类型展示信息与伤害来源触发规则 | 系统/数值策划 |

## 页签一览

| 页签 | 当前数据量 | 用途 | 主要关联 |
|------|------------|------|----------|
| `HeroBondsSkillCfg` | 30 行 | 维护每种机制各等级的效果值与解锁升级条件 | `Type` 关联 `HeroBondsSkillTypeCfg.ID` |
| `HeroBondsSkillTypeCfg` | 6 行 | 维护六类机制对应的属性、名称、描述与展示信息 | `ID` 被等级表及触发顺序引用 |
| `HeroBondsSkillTriggerCfg` | 4 行 | 维护不同伤害来源允许触发的机制、运算顺序与触发链限制 | `TriggerOrder` 填机制类型 ID |

## 配置关系

- `HeroBondsSkillCfg.Type` 关联 `HeroBondsSkillTypeCfg.ID`。
- `HeroBondsSkillCfg.Value` 按数组位置对应 `HeroBondsSkillTypeCfg.BuffProperty`。
- `HeroBondsSkillTriggerCfg.TriggerOrder` 按顺序填写 `HeroBondsSkillTypeCfg.ID`。

## 公共口径

| 枚举 | 含义 |
|------|------|
| `Type=1` | 暴击 |
| `Type=2` | 克制强化 |
| `Type=3` | 闪避 |
| `Type=4` | 额外伤害 |
| `Type=5` | 反击强化 |
| `Type=6` | 连击 |

- `HeroBondsSkillTypeCfg.BuffProperty` 与 `HeroBondsSkillCfg.Value` 按数组下标一一对应。
- 当前暴击配置包含两个属性值，其余五类机制各包含一个属性值。
- 效果值按字段注释填写绝对值或万分率；具体单位由对应属性 ID 的既有定义决定。
- 解锁升级条件使用 `Expression_P` 数组；空数组 `[]` 表示该等级没有附加数量条件。
- 条件仅用于判定新的解锁或升级资格。已获得的机制解锁和等级记录按主案永久保留，不因条件调整而回退。

# 机制等级配置

## HeroBondsSkillCfg

一行代表一种机制的一个等级。当前六种机制均配置 5 级，共 30 行。

| 字段 | 类型 | 读取端 | 说明 | 填表要点 |
|------|------|--------|------|----------|
| `Id` | int | cs | 等级配置唯一 ID | 当前数据采用“机制类型千位段 + 等级”的结果值，如暴击 1 级为 1001；发布值必须唯一 |
| `Type` | int | cs | 机制类型 | 填 1–6，并关联 `HeroBondsSkillTypeCfg.ID` |
| `Level` | int | cs | 机制等级 | 同一 `Type` 内保持唯一并按升序维护；当前范围为 1–5 |
| `Value` | int\[\] | cs | 本等级效果值列表 | 数组长度与该类型的 `BuffProperty` 长度一致，并按相同下标对应 |
| `Filters` | ext\[\] | cs | 解锁升级条件 | 第 5 行结构标记为 `Expression_P`；无条件填 \[\] |

### Filters 条件结构

当前配置使用以下三个键：

| 键 | 当前取值 | 说明 |
|----|----------|------|
| `op` | `ge` | 大于等于 |
| `typ` | `heroType1`–`heroType5` | 参与统计的五星英雄类型 |
| `val` | 非负整数 | 达成该等级所需的英雄数量 |

`typ` 的 Excel 枚举如下：

| typ | 统计口径 |
|-----|----------|
| `heroType1` | 五星弓英雄数量 |
| `heroType2` | 五星火英雄数量 |
| `heroType3` | 五星冰英雄数量 |
| `heroType4` | 五星毒英雄数量 |
| `heroType5` | 五星任意英雄数量 |

填写示例：

```json
[{"op":"ge","typ":"heroType1","val":3}]
```

表示五星弓英雄数量大于等于 3。无附加条件时填写：

```json
[]
```

# 机制类型配置

## HeroBondsSkillTypeCfg

一行代表一种机制类型。当前配置六行，`ID` 与机制枚举 1–6 一一对应。

| 字段 | 类型 | 读取端 | 说明 | 填表要点 |
|------|------|--------|------|----------|
| `ID` | int | cs | 机制类型 ID | 当前固定为 1–6；同时被等级表 `Type` 与触发表 `TriggerOrder` 引用 |
| `BuffProperty` | int\[\] | cs | 属性 ID 列表 | 数组顺序决定等级表 `Value` 的参数顺序 |
| `Name` | string | cs | 机制名称 | 当前填写 `HeroBondsSkill_name_01`–`06` 多语言文本键 |
| `Desc` | string | cs | 机制描述 | 当前填写 `HeroBondsSkill_desc_01`–`06` 多语言文本键 |
| `StyleId` | int | c | 飘字颜色样式 ID | 引用客户端已有样式；不直接填写颜色值 |
| `Priority` | int | c | 展示优先级 | 按客户端既有优先级规则填写 |
| `Enable` | bool | c | 是否显示 | 仅客户端读取；不得解释为机制解锁、升级或结算开关 |
| `Icon` | string | c | 图标资源键 | 填写资源键，不填写文件系统路径 |
| `IsShowUI` | bool | c | 是否在 UI 上显示 | 控制 UI 展示标记；仅客户端读取 |

### 两个展示字段的边界

- `Enable` 与 `IsShowUI` 均按 Excel 表头保留为客户端展示字段。
- Excel 当前注释未继续拆分两个字段的具体展示场景，派生文档不额外赋予解锁、升级、存档或战斗结算含义。
- 如客户端需要调整两者的职责，应先修改 Excel 表头注释或补充程序约定，再同步更新本文。

# 触发规则配置

## HeroBondsSkillTriggerCfg

一行代表一种伤害来源的机制触发规则。当前覆盖普通攻击、连击伤害、额外伤害与反击伤害四类来源。

| 字段 | 类型 | 读取端 | 说明 | 填表要点 |
|------|------|--------|------|----------|
| `Id` | int | cs | 触发规则唯一 ID | 当前与 `SourceType` 一一对应，必须唯一 |
| `SourceType` | int | cs | 伤害来源类型 | 1=普通攻击（根行为），2=连击伤害，3=额外伤害，4=反击伤害 |
| `CanCritical` | int | cs | 是否允许暴击 | 0=否，1=是 |
| `ApplyRestraint` | int | cs | 是否应用克制强化 | 0=否，1=是 |
| `CanDodge` | int | cs | 是否允许闪避 | 0=否，1=是 |
| `CanExtraDamage` | int | cs | 是否允许额外伤害 | 0=否，1=是 |
| `CanCounter` | int | cs | 是否允许反击 | 0=否，1=是 |
| `CanCombo` | int | cs | 是否允许连击 | 0=否，1=是 |
| `TriggerOrder` | int\[\] | cs | 机制运算顺序 | 数组元素填机制类型 ID，并严格按数组顺序执行；不允许触发时填 \[\] |
| `CounterMode` | int | cs | 反击计数模式 | 0=不允许反击，1=每个伤害段独立判定，2=同一 RootAction 对同一目标最多触发 1 次 |
| `MaxChainDepth` | int | cs | 最大触发链深度 | RootAction 深度为 0，派生行为深度为父行为深度 +1；超过上限不生成；0 表示不设上限 |

### 当前伤害来源规则

| SourceType | 来源 | 暴击 | 克制强化 | 闪避 | 额外伤害 | 反击 | 连击 | TriggerOrder | CounterMode | MaxChainDepth |
|------------|------|------|----------|------|----------|------|------|--------------|-------------|---------------|
| 1 | 普通攻击（根行为） | 是 | 是 | 是 | 是 | 是 | 是 | `[3,2,1,6,4,5]` | 2 | 2 |
| 2 | 连击伤害 | 是 | 否 | 是 | 否 | 是 | 否 | `[3,1,5]` | 2 | 2 |
| 3 | 额外伤害 | 否 | 否 | 否 | 否 | 否 | 否 | \[\] | 0 | 2 |
| 4 | 反击伤害 | 是 | 否 | 是 | 否 | 否 | 否 | `[3,1]` | 0 | 2 |

# 配置校验

- 工作簿必须保留 `HeroBondsSkillCfg`、`HeroBondsSkillTypeCfg`、`HeroBondsSkillTriggerCfg` 三个页签及其现有字段名；增删字段需同步双端导表与本文。
- `HeroBondsSkillCfg.Id`、`HeroBondsSkillTypeCfg.ID`、`HeroBondsSkillTriggerCfg.Id` 分别在各自页签内唯一。
- 等级表的 `Type` 必须存在于类型表；同一 `Type + Level` 组合不得重复。
- 等级表 `Value` 的元素数量必须等于类型表 `BuffProperty` 的元素数量，且数组下标含义一致。
- `Filters` 必须是合法 JSON 数组；无条件使用 `[]`，不能留空。当前只使用 `op=ge` 与 `heroType1`–`heroType5`。
- 类型表的 `Name`、`Desc` 多语言文本键和 `Icon` 资源键必须存在。
- `Enable`、`IsShowUI` 使用布尔值；触发表六个允许项使用整数 0/1，不混用其他值。
- `TriggerOrder` 中每个类型 ID 必须存在于类型表，同一顺序数组内不得重复。
- `CounterMode` 只能填 0–2；`MaxChainDepth` 不得为负数。
- 表内公式单元格导出前必须能够得到有效缓存值；当前等级表第 14–38 行的 `Id`、`Type`、`Level` 使用公式生成，策划修改引用行后需重新计算并保存工作簿。
